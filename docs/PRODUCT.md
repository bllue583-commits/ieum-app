# 이음 — 앱 목적·기능·UX 설계서 (v1013 기준, 2026-10-30)

> 이 문서는 "무엇을, 누구를 위해, 어떻게 보여줄지"를 정리합니다. 개발 진행·환경은 [HANDOFF.md](HANDOFF.md)를 보세요.

---

## 1. 앱의 목적

### 1.1 해결하려는 문제
- 사용자(아내)는 **건설사 직원**으로 현장 하나를 맡고 있고, 협력업체·사내 직원과 **하루 약 2시간** 통화한다.
- 통화가 많아 **저녁이 되면 누구와 무슨 약속을 했는지 기억하지 못한다.** 메모할 틈도 없다.
- 놓치는 것: 보내기로 한 서류(견적서·도면·계약서), 다시 연락하기로 한 약속, 업체별 진행 상황, 이름과 소속.

### 1.2 목표
1. **아무것도 누르지 않아도** 통화가 끝나면 자동으로 정리된다.
2. 저녁에 **"오늘 무슨 통화를 했고 뭘 해야 하는지"**를 한 화면에서 본다.
3. 아침에 **오늘 할 일**을 알림으로 받는다 (앱을 열지 않아도 읽을 수 있게).
4. 업체·사람별 **맥락이 쌓여서** 다음 통화 정리가 점점 정확해진다.
5. **녹음 파일은 휴대폰 밖으로 나가지 않는다.** (개인정보 보호)

### 1.3 사용자와 기기
| 항목 | 내용 |
|---|---|
| 실사용자 | 건설사 직원(아내). 스마트폰은 익숙하지만 앱 설정을 만지는 건 싫어함 |
| 관리자 | 남편(앱 요청자). 개발은 Claude가 전담, 사용자는 "시작/중지"만 지시 |
| 기기 | Galaxy S25 (삼성 통화 녹음 사용, 녹음은 `Recordings/Call` 폴더에 m4a) |
| UX 기준 | **50대 남자가 봐도 편하고, 어떤 기능이 있는지 바로 알 수 있게** |
| 디자인 요구 | 깔끔한 것을 넘어 **세련되게**. 현재는 "깔끔하지만 세련되지 않음" 평가(10/30) |

### 1.4 하지 않는 것 (범위 밖)
- 녹음 파일을 서버로 보내는 것, 통화 내용을 외부 서비스(구글 드라이브·카톡 등)에 저장하는 것 — 예전에 있던 기능을 삭제함
- AI가 할 일을 **완료 처리**하는 것 (완료는 사람만)
- 자막에 근거가 없는 할 일·사람·업체를 만드는 것

## 2. 전체 동작 (사용자에게 보이지 않는 부분)

```
① 통화 종료
② 녹음 감지: 선택한 녹음 폴더를 감시(15분 주기 + 변경 감지), 새 m4a 발견
③ 폰에서 Whisper(574MB 한국어 모델)로 자막 생성
   - 침묵 구간 건너뛰기, 발열 심하면 자동 일시정지, 배터리 부족 시 대기
   - S26 기준 녹음 1분당 약 72~85초
④ 자막 + 맥락(현장 메모, 상대 사람·업체 카드, 최근 통화, 열린 할 일, 이름 목록)을
   비공개 우편함(GitHub ieum-inbox/inbox)에 올림 — 녹음 파일은 안 올림
⑤ Claude 예약 작업(매시 정각, 07~23시, Sonnet 5.5)이 분석해 results/에 결과를 씀
⑥ 폰이 결과를 받아 검증(근거 문장 대조, 없는 이름 버림) 후 적용, 우편함 파일 삭제
⑦ 저녁 7시: "오늘의 통화" 정리 알림 / 아침 6시: "오늘 할 일" 알림
⑧ 앱 업데이트: 개발자가 코드를 올리면 자동 빌드 → 폰이 새 버전 안내
```

### 분석 결과에 들어가는 것
| 항목 | 설명 |
|---|---|
| 요약 | 2~3문장: 누구와, 무슨 일로, 무엇이 정해졌나 |
| 중요한 내용 | 짧은 글머리표 몇 개 |
| 약속 | 누가(내가/상대가) 무엇을 언제까지, **자막 원문 인용** 포함 |
| 할 일 | 새로 만들기 / 기존 할 일 갱신. 업체 이름이 붙음 |
| 상대 | 이름, 소속 업체, 직함, 우리 직원 여부 |
| 장부 갱신 | 현장 상황 메모, 업체 메모, 업체 공종(철근·타설·전기…) |

### 안전장치
- 자막에 실제로 나온 할 일만 유지 (인용문이 자막과 글자 그대로 일치해야 함)
- 자막·이름 목록에 없는 사람/업체 이름은 버림
- 사용자가 고친 할 일, 완료한 할 일은 AI가 바꾸지 않음
- 자막 안의 "지시"는 따르지 않고 데이터로만 다룸

## 3. 기능 목록 (화면별)

### 3.1 홈
| 요소 | 기능 |
|---|---|
| 제목 "이음" + 날짜 · "오늘의 통화를 대신 기억해요" | 앱 정체성 |
| **처음 설정 카드** (n/5) | 남은 단계를 하나씩만 크게 보여줌: ① 녹음 폴더 연결 ② 정리 동의(버튼 한 번) ③ 음성 인식 모델 받기(Wi-Fi, 570MB) ④ 알림 허용 ⑤ 배터리 제한 풀기. 끝난 단계는 ✓ |
| 오늘 요약 시트 | 통화 n건 · 새로 생긴 할 일 n개 · 오늘까지 할 일 n개 · 다음 알림 시각 · 마지막 정리 시각 |
| 이동 행 4개 | 오늘의 통화 / 할 일 / 업체·사람 보기 / 설정 (각 행에 상태 한 줄) |
| 새 버전 안내 | 업데이트가 준비되면 상단에 표시 |

### 3.2 오늘의 통화
| 요소 | 기능 |
|---|---|
| 날짜 이동 | ◀ 전날 / 오늘로 / 다음날 ▶ |
| 오늘 할 일 | 그날까지의 할 일 최대 5개 + "외 n개", [할 일 전체 보기] |
| 통화 카드 | 시각 · 상대(이름 · 업체), 요약, 약속 한 줄, "눌러서 자세히 보기 ›". 실패한 통화는 경고 색 |
| 통화 상세 | 요약 / 중요한 내용 / 약속(원문 인용) / 할 일 목록에 반영한 것 / [통화 내용 전체 보기](자막, 14일 보관) |

### 3.3 할 일
| 요소 | 기능 |
|---|---|
| 남은 할 일 n개 | 묶음: 기한 지난 일 / 오늘까지 / 끝났는지 확인해 주세요 / 다가오는 일 / 기한 없는 일 (빈 묶음은 숨김) |
| 할 일 카드 | [업체명], 할 일 제목, 기한 배지, "○○ 님과의 통화에서", [완료했어요] |
| 공정표 막대 | 카드 왼쪽 세로 막대: 기한 지남 빨강, 오늘 앰버 |
| 상태 | 확인 필요 / 진행 중 / 기다리는 중 |

### 3.4 업체·사람 보기 (10/30 개편)
| 요소 | 기능 |
|---|---|
| 업체 목록 | 최근 통화 순. 업체명, 공종 배지, 열린 할 일 수, 마지막 통화일, "사람·메모 자세히 보기 ›" |
| 업체 없는 사람 | 우리 직원 등 소속 업체가 없는 사람 목록 |
| 업체 상세 | 업체 메모(AI가 통화마다 갱신) / 사람(n) / 열린 할 일 / 최근 통화 10건 |
| **이름 고치기** | 사람 카드마다 버튼 → 대화상자에서 바른 이름 입력 → 저장. 옛 이름은 별칭으로 기억해 같은 오인식이 와도 같은 사람에 연결. 고친 이름은 모든 화면·알림·AI 이름 목록에 반영 |

### 3.5 설정
| 항목 | 내용 |
|---|---|
| 1. 녹음 폴더 | 연결 상태, [폴더 바꾸기] |
| 2. 통화 정리 방식 | 구독 방식이면 "자동 정리 ✓ 따로 넣을 키가 없어요". (우편함 없는 빌드에서는 API 키 입력) |
| 3. 정리 동의 | 켜기/끄기 스위치, 녹음 파일은 폰 밖으로 안 나간다는 설명 |
| 4. 음성 인식 모델 | 준비됨/받는 중/실패, [모델 받기] |
| 5. 알림 시각 | 저녁 정리(기본 19시), 아침 보고(기본 6시) |
| 현장 상황 메모 | AI가 쓰는 현장 요약(공정·이슈·일정) 보기 |
| 지금 상태 | 처리 대기/완료/실패 건수, 녹음 1분 처리 시간, [모두 다시 분석] |

### 3.6 알림
| 알림 | 시각 | 내용 | 누르면 |
|---|---|---|---|
| 저녁 정리 | 19:00 | "오늘 통화 n건" + 상대 이름 2명 + 각 통화 한 줄 | 오늘의 통화 |
| 아침 보고 | 06:00 | "오늘 할 일 n개" + "• [업체] 할 일 — 기한" 목록(펼치면 전부 보임) | 할 일 |

## 4. UX 설계 원칙

### 4.1 핵심 원칙
1. **버튼 없는 자동화** — 설정을 마친 뒤 사용자가 할 일은 "읽기"와 "완료했어요" 누르기뿐.
2. **한눈에 기능이 보이는 홈** — 홈의 이동 행 4개가 앱의 전부. 숨은 메뉴·햄버거 메뉴 없음.
3. **한 번에 한 단계** — 처음 설정은 지금 할 단계 하나만 크게, 나머지는 목록.
4. **큰 글씨, 쉬운 말** — 버튼 외 모든 글자 18sp 이상, 영어 상태값(FAILED 등)·전문용어 노출 금지, "~해요" 체. (자동 테스트로 강제됨)
5. **근거를 보여준다** — 약속·할 일에는 통화 원문 인용을 붙여 "AI가 지어낸 게 아님"을 확인할 수 있게.
6. **AI는 제안, 사람이 결정** — 완료 처리·이름 수정은 사람만.
7. **알림만 읽어도 된다** — 아침 보고는 앱을 열지 않아도 할 일 전부가 보이게.
8. **개인정보** — 녹음은 폰 안에만, 자막은 14일 후 삭제(요약은 유지).

### 4.2 화면 흐름
```
홈 ─┬─ 오늘의 통화 ── 통화 상세 ── 통화 내용 전체
    ├─ 할 일
    ├─ 업체·사람 보기 ── 업체 상세 ── 이름 고치기(대화상자)
    └─ 설정
알림(저녁) → 오늘의 통화 / 알림(아침) → 할 일
```

### 4.3 시각 디자인 (설계도 "화면 디자인" 절)
| 요소 | 값 |
|---|---|
| 콘셉트 | 현장 업무 도구: 도면·공정표에서 가져온 절제된 색 |
| 바탕 | 콘크리트 회색 `#F2F4F5` |
| 시트 | 흰색 + 얇은 테두리 `#DCE1E5`, 그림자 없음 |
| 주 색 | 도면 청색 `#1F5C99` |
| 주의 | 앰버 글자 `#A86F00`, 막대 `#E3A21A` |
| 기한 지남 | `#B23A2B` |
| 포인트 | 할 일 카드 왼쪽 **공정표 막대** |
| 금지 | 그림자, 이모지 |
| 구현 | XML/Compose 없이 코드로 View 생성, 공통 스타일은 `CallUi.kt` |

### 4.4 현재 디자인의 한계 (사용자 평가: "깔끔하지만 세련되지 않음")
S26 스크린샷 기준으로 Claude가 판단한 원인:
1. **모든 버튼이 같은 연청색 큰 덩어리** — 전날/다음날, 전체 보기, 이름 고치기, 완료했어요가 같은 무게. 주요·보조 동작 구분 없음 → 화면이 투박해 보임.
2. **아이콘·그래픽 요소 없음** — 이모지를 금지하면서 대체 아이콘도 없어 글자만 나열됨. 기능을 "한눈에" 알기 어려움.
3. **위계 부족** — 숫자(통화 3건, 할 일 2개) 같은 핵심 정보가 본문과 비슷한 크기. 대시보드 느낌이 없음.
4. **같은 정보가 화면마다 다른 모양** — 할 일이 글머리표 한 줄 / 카드 / 또 다른 카드.
5. **줄 간격이 넓고 문단이 길다** — 카드가 세로로 늘어져 한 화면에 정보가 적음.
6. **상단 바·뒤로 가기 없음** — "← 업체 목록으로"가 본문 버튼. 내비게이션 구조가 화면마다 다름.
7. **시스템 내비게이션 바와 겹침** (버그) — 화면 아래 글자가 내비게이션 바 뒤로 들어감.
8. 여백·정렬 리듬이 일정하지 않음, 배지(철근·오늘까지)가 평범한 태그처럼 보임.

### 4.5 개편 방향 (다음 작업)
- **목표:** 정보 밀도는 높이고, 위계는 분명하게, 50대 가독성은 유지 — "현장 소장이 쓰는 잘 만든 업무 도구".
- 버튼 체계 3단계: 주요(채움) / 보조(테두리) / 텍스트 링크. 화면당 주요 버튼은 최대 1개.
- 선 아이콘 세트 도입(통화·할 일·업체·설정·기한·완료) — 벡터 드로어블, 단색.
- 홈을 **대시보드형**으로: 큰 숫자 타일(오늘 통화 / 남은 할 일 / 기한 지남), 그 아래 "지금 할 일" 3개.
- 공통 컴포넌트 통일: 할 일 행 하나의 모양을 모든 화면에서 재사용.
- 상단 바(제목 + 뒤로) 공통화, edge-to-edge 인셋 처리.
- 타이포 스케일 재정의(제목 28 / 섹션 20 / 본문 18 / 보조 16sp, 줄 간격 1.35 내외), 8dp 그리드.
- 검증: device-test 스크린샷으로 전후 비교, 50대 기준 테스트(18sp·영어 금지) 유지.

## 5. 데이터 (폰 안 암호화 DB)
| 표 | 내용 |
|---|---|
| `call_records` | 통화별 자막·요약·분석 결과·상태(TRANSCRIBED/ANALYZED/FAILED/WAITING_*) |
| `workflow_items` | 할 일·서류 (제목, 기한, 상태, 근거 인용) |
| `companies` | 업체명, 공종, 메모 |
| `people` | 이름, 전화번호 키, 소속 업체, 직함, 우리 직원 여부 |
| `person_aliases` | 사용자가 고치기 전 이름(공백 제거) → 사람 |
| `call_links` / `task_companies` | 통화↔사람·업체, 할 일↔업체 연결 |
| `site_memo` | 현장 상황 메모 1개 |

- DB 전체가 암호화되어 저장(16MB 이하 유지), 자막은 14일 후 비움.

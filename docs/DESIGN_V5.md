## 1. 보고 형식 (루틴이 쓰고 폰이 그대로 보냄)

`ieum-inbox/report/YYYY-MM-DD.json` (KST 날짜 = 보고 날짜 = "오늘"):
```json
{"day":"2026-11-07","generatedMs":1793996000000,"tidyRev":12,
 "head":{"calls":7,"newChecks":3,"todayChecks":5,"issues":2},
 "yesterday":[{"who":"△△철강 김민수 대표","what":"철근 단가 재협의, 견적서 금요일까지 보내기로"},
              {"who":"○○전기","what":"배선 자재 내일 입고, 검수 입회 요청"}],
 "today":[{"id":"t_…","what":"견적서 보내기","who":"△△철강","since":"어제 요청","status":"","check":false},
          {"id":"t_…","what":"안전 점검 서류","who":"본사 박과장","since":"3일 전 요청","status":"메일 발송 확인 완료","check":false}],
 "inProgress":[{"what":"철근 단가 재견적: 업체 회신 대기, 금요일 계약 예정"}],
 "check":[{"what":"13층/30층 중 어느 쪽인지","who":"△△철강"}]}
```
- `yesterday`: 어제(KST) 업무 통화·문자·메일을 **업체(또는 사람) 단위로 묶어** 한 줄씩, 중요한 순서(약속·금액·날짜가 있는 것 먼저), 최대 8줄. 통화가 0건이면 빈 배열. 개인 통화는 넣지 않는다.
- `today`: 열린 체크할 일 중 **오늘·어제 요청과 "확인 필요"를 먼저**, 그다음 요청 순, 최대 8줄. `status`는 맥락을 종합한 상태 글("메일 발송 확인 완료", "문자로 답 받음", 없으면 빈 문자열) — 11/6 08:26 결정대로 "언제까지"·"지났어요"는 쓰지 않는다. `since`는 요청 날짜 표현("오늘 요청", "어제 요청", "3일 전 요청").
- `inProgress`: 장부 issues 중 어제 움직임이 있던 것 먼저, 최대 3줄. `check`: 확인 필요(tentative) 항목 최대 3줄.
- 글 규칙은 화면과 같다: 가운데 점·말줄임표·영어 상태값·"기한"·"지남" 금지, "~해요"체 아닌 보고체(명사형 종결), 전화번호·금액 외 민감 정보 없음(금액·수량·날짜는 적는다). 전화번호는 절대 넣지 않는다.

**카톡 메시지 조립(폰, `KakaoReport.compose`)** — 각 통은 200자 이하(한글 1자 = 1자, 줄바꿈 포함), 넘치면 줄 단위로 자르고 마지막에 "외 n건". 통 수는 내용이 있는 것만, 최대 4통, 순서대로:
```
① [이음 아침 보고] 11/7(금)
   어제 통화 7건, 새 체크 3개, 오늘 챙길 일 5개
   어제 정리
   1. △△철강 김민수 대표: 철근 단가 재협의, 견적서 금요일까지 보내기로
   2. ○○전기: 배선 자재 내일 입고, 검수 입회 요청
② [어제 정리 계속] 3. … (①에 다 못 들어갔을 때만)
③ [오늘 챙길 일]
   1. 견적서 보내기 (△△철강, 어제 요청)
   2. 안전 점검 서류 (본사 박과장, 메일 발송 확인 완료)
④ [진행 중·확인]
   진행 중: 철근 단가 재견적, 업체 회신 대기
   확인 필요: 13층/30층 중 어느 쪽인지 (△△철강)
```
- 모든 통에 버튼 [이음에서 보기]: ①·②는 통화 탭(어제 날짜), ③·④는 체크 탭. 카카오 텍스트 템플릿의 `link`에 앱 실행 파라미터(`screen=calls&dayMs=…`, `screen=tasks`)를 넣고 `MainActivity.intent`가 그대로 받는다(앱이 없으면 아무것도 안 함 — 아내 폰에만 쓰는 것이라 스토어 링크 없음).
- 보고서가 없거나 날짜가 다르면(루틴 실패) 폰 자료로 **1통만**: "[이음 아침 보고] 11/7(금) (새벽 정리 없이 폰에서 만든 보고)" + 오늘 챙길 일 상위 4개(홈 `firstLook`과 같은 규칙).

### 2.1 묶음 r15-1 카카오 전송 (앱)
1. **연결:** 설정 "아침 보고" 묶음의 [카카오톡으로 받기] → 카카오 SDK 로그인(카카오톡 앱 있으면 앱으로, 없으면 계정 로그인) → 동의 항목 `talk_message`만 요청(프로필·친구 목록은 요청하지 않는다). 성공하면 `KAKAO_LINKED=true`, 줄에 "연결됨, 매일 5:30에 보내요". SDK가 토큰 갱신을 맡는다(refresh 토큰은 쓸 때마다 연장). `KakaoSdkError.InvalidToken`류면 `KAKAO_LINKED=false`로 내리고 신호등·자가 진단에 "카카오톡 연결이 풀렸어요, 설정에서 다시 연결"(r15-3 문구).
2. **보고서 받기(`ReportFetch`):** 고유 작업 `ieum.report.morning`을 매일 05:30(KST, `MORNING_HOUR` 설정과 별개 상수 `REPORT_SEND_HOUR=5, MINUTE=30`)에 등록. `report/<오늘>.json`을 ETag로 읽고(없으면 404), 있으면 설정 `REPORT_DAY`와 본문 저장 → 전송. 없으면 +5·+15·+30분 재시도(05:35, 05:45, 06:00). 06:00에도 없으면 폰 폴백 1통(1절)과 `report.source="phone"`.
3. **전송(`KakaoReport.send`):** `compose()`가 만든 통을 순서대로 `TalkApiClient.sendDefaultMemo(TextTemplate)`로, 통 사이 1초, 실패하면 그 통만 1회 재시도. 모두 성공이면 `KAKAO_LAST_SENT_MS`, `KAKAO_SENT_COUNT`+1; 하나라도 실패면 `KAKAO_FAILED_COUNT`+1, `KAKAO_LAST_ERROR`(코드 80자), 앱 알림 폴백(r15-3). **같은 날 두 번 보내지 않는다**(`REPORT_DAY` 비교). 네트워크 없으면 WorkManager 제약으로 기다렸다가 최대 09:00까지만(그 뒤는 보내지 않고 앱 알림만).
4. **개인정보:** 카톡 본문에는 이름·업체·요약·체크할 일이 들어간다(카카오 서버를 거침). 전화번호·자막·문자 원문·금액 외 식별 정보는 넣지 않는다(`compose`가 `maskNumbers`를 한 번 더 통과시킨다). 보고서 JSON은 우편함(비공개)에 남고 30일 뒤 루틴이 지운다(r15-2).
5. 시험: `compose` 고정 사례 6개(0건·1건·8건·넘침 "외 n건"·확인 필요·폴백), 각 통 ≤ 200자, 전화번호 없음, 같은 날 재전송 금지, 404 → 재시도 체인 → 폴백, 토큰 실패 → linked=false.

## 3. 확인 기준
- 단위 전체 + `RoutineDocTest`(v7) + `report_check.py`·`test_watchdog.py`. 각 통 ≤ 200자, 전화번호 0.
- 배포 뒤 3일: 매일 04:46 `report/<날짜>.json` 생성(워치독 조용), 05:30~05:45 사이 카톡 4통 이내 도착(아내 확인 1회), 하트비트 `kakao.sent` 3, `failed` 0, `report.source="routine"` 3/3. 아침 앱 알림은 0건(카톡 성공 시).

## 4. 사용자가 할 일 (코드와 무관, 지금 가능)
1. [카카오 developers](https://developers.kakao.com)에서 앱 하나 만들기(이름 "이음"), **플랫폼 › Android**에 패키지 `kr.callbrief`와 키 해시 등록(키 해시는 release-apk 로그에 찍어 주도록 r15-1이 넣음 — 그 전에는 첫 배포 뒤 로그에서 복사), **카카오 로그인 활성화**, **동의 항목 › 카카오톡 메시지 전송(`talk_message`)** 을 "선택 동의"로 켜기. 앱 검수는 필요 없다(본인 계정 "나에게 보내기"는 검수 없이 됨 — (확인 필요: 팀원 등록으로 충분한지)).
2. 네이티브 앱 키를 GitHub 비밀 `IEUM_KAKAO_APP_KEY`에 넣기(앱 키는 비밀은 아니지만 저장소가 공개라 코드에는 두지 않는다).
3. 아내 카카오 계정을 developers 앱의 **팀원**으로 등록(검수 전 상태에서 팀원만 로그인 가능).
4. 배포 뒤 아내 폰에서 설정 › 아침 보고 › [카카오톡으로 받기] 한 번.
5. (선택, v3.6 재료) 관리자(남편)에게도 보내기: "친구에게 보내기"는 `friends` 동의와 친구 관계가 필요하고 하루 한도가 있어, 필요하면 따로 설계.

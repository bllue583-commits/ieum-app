# 이음 v2.5 화면 코드 검증 (work-v25, 읽기 전용)

대상: `android/app/src/main/java/kr/callbrief/pipeline/` 의 HomeActivity, TodayCallsActivity, CallTasksActivity, CompaniesActivity, CallSettingsActivity, CallUi, CallIcons, LaunchIntro, PhoneStatus, SelfCheckNotices, PreviewSeed, TaskActions, ScreenParts, StatusLights, CallFolder와 저장 계층 `call-core-android/.../ProtectedDatabase.java`, 관련 단위 테스트 8개. 기준 문서는 설계도의 "보고와 화면", "화면 디자인", "3회차 결정 사항", "G절", "v2.0 대조 결정", 그리고 reviews/20261104_B 6~7절과 HANDOFF 5절입니다.
표기 규칙: **[근거]**는 코드에서 직접 확인한 것이고, **[추정]**은 코드로 짐작했지만 기기에서 재 보지 않은 것(시간, 체감 등)입니다.

---

## 요약 (심각한 것부터 5줄)

1. **[근거] 근본 원인: DB를 한 번 열고 쓸 때마다 저장소 전체를 다시 처리합니다.** DB를 처음 열 때는 파일 전체를 복호화해 메모리 SQLite에 다시 넣고, 열 때마다 DB 전체를 JSON으로 바꿔 비교하며, 쓸 때마다 DB 전체를 암호화하고 fsync합니다. 모든 쿼리는 Keystore 확인을 거치고, 읽기와 쓰기가 백그라운드 작업과 같은 잠금 하나를 씁니다. 홈 화면 하나를 읽는 동안 이런 열기가 6번, 기다리는 기록 1건마다 쿼리가 2번 더 생깁니다. 그래서 버튼을 누른 뒤 결과가 화면에 나올 때까지 아무 표시도 없는 시간이 길어집니다. 실제로 몇 초인지는 [추정]입니다.
2. **[근거] 지금 보고 있는 탭을 다시 누르면 아무 일도 일어나지 않습니다(`CallUi.kt:168`).** 통화나 업체 상세에서 "통화" 탭을 눌러 목록으로 가려 해도 반응이 없습니다. 게다가 다른 화면에서 열어 둔 통화 상세가 REORDER_TO_FRONT로 다시 앞에 나와, "통화" 탭을 눌렀는데 목록 대신 엉뚱한 통화 상세가 보이기도 합니다.
3. **[근거] 알림으로 앱을 열면 뒤로 가기로 앱을 끝낼 수 없습니다.** 알림은 체크, 통화, 설정 화면을 새 작업의 맨 아래로 엽니다. 그 위에 홈이 쌓이면 홈에서 뒤로를 눌러도 아래 화면으로 돌아가고, 거기서 뒤로를 누르면 다시 홈이 열리는 순환에 빠집니다.
4. **[근거] [다 됐어요]를 누른 뒤 저장이 끝날 때까지 아무 표시가 없고, 두 번 누르는 것도 막지 못합니다.** 행을 끄는 코드가 부모 행만 끄고 버튼 자체는 그대로 둡니다. 그래서 두 번째 누름이 "바꾸지 못했어요. 다시 시도해 주세요." 토스트를 띄웁니다. 실제로는 이미 완료된 상태입니다.
5. **[근거] 눌러도 결과가 바뀌지 않는 버튼과, 누르면 상태를 잃는 화면이 있습니다.**
   - [다시 정리하기]: 정리 실패의 유일한 원인이 빈 자막이라 다시 눌러도 또 실패합니다.
   - [알림 허용하기]: 두 번 거절한 뒤에는 눌러도 아무 일이 없습니다.
   - 직접 적은 체크할 일의 행을 누르면 매번 "통화를 찾지 못했어요"가 뜹니다.
   - 설정에서 무엇을 바꾸든 화면이 맨 위로 튀고, 메일 칸에 적던 주소와 비밀번호가 지워집니다.
   - "저장 공간 %"는 존재하지 않는 경로를 보기 때문에 한 번도 나오지 않습니다.

## 2. "버튼 무반응"으로 느껴지는 원인 종합

남편이 말한 "버튼을 눌렀을 때 반응을 안 한다"는 아래 다섯 가지가 겹쳐 생깁니다. 위에 있을수록 자주, 넓게 생깁니다.

**근본 원인 A: 화면 데이터 읽기와 쓰기가 무겁고, 결과가 나오기 전까지 아무 표시가 없습니다. [근거, 시간은 추정]**
- 모든 화면은 IO 스레드에서 DB를 읽은 뒤에야 다시 그립니다. 메인 스레드를 막는 구조는 아닙니다.
- 문제는 IO 자체가 무겁다는 것입니다.
  - 핸들이 없을 때 여는 비용은 파일 전체를 AES-GCM으로 복호화하고 메모리 DB에 모든 행을 다시 넣는 것입니다(`ProtectedDatabase.java:114-126`).
  - 열 때마다 생성자 transaction이 전체 스냅샷을 만듭니다(`CallRecordStore.kt:150-170`, `ProtectedDatabase.java:156`).
  - 쿼리마다 Keystore 확인을 거칩니다(137).
  - 쓸 때마다 전체 스냅샷, 암호화, fsync, 다시 읽기 확인을 합니다(156-160, 168-183).
  - 읽기와 쓰기가 State 하나에 `synchronized`로 묶여 있어(78-80, 146-147), 매시간 분석이나 자막 작업이 한 문장짜리 transaction을 연달아 실행하는 동안 화면의 읽기는 순서를 기다립니다.
- 홈 화면 하나에 스토어 열기 6번과 기록별 쿼리 2번이 붙고(`HomeActivity.kt:87-111`), 통화 화면은 들어올 때마다 10/1 이후 통화기록 전체를 다시 맞춥니다(`TodayCallsActivity.kt:63`).
- 처음 연 화면은 그 시간 동안 빈 회색 화면이고, 다시 연 화면은 예전 내용이 그대로 있어 누른 것이 반영되지 않은 것처럼 보입니다.
- 눌림 표시(리플)는 거의 모든 곳에 있습니다(이 부분은 v2.0에서 고쳐졌습니다). 하지만 "처리 중" 표시(버튼 끄기, 글자 바꾸기, 불러오는 중)는 어디에도 없습니다.

**원인 B: 일부러 무시하도록 만든 누름. [근거]**
- 현재 탭을 다시 누르면 무시합니다(`CallUi.kt:168`). 상세에서 목록으로 가려는 가장 자연스러운 동작이 막혀 있습니다.
- 설정의 `busy` 동안 다른 모든 버튼을 조용히 무시합니다(`CallSettingsActivity.kt:127`).

**원인 C: 처리는 되었는데 결과가 눈에 보이지 않거나 실패처럼 보입니다. [근거]**
- [다 됐어요]: 저장이 끝난 뒤에야 흐려지고, 두 번째 누름은 실패 토스트를 띄웁니다(`TaskActions.kt:17-23`).
- [모델 받기]: 와이파이 전까지 아무 변화가 없습니다.
- [다시 정리하기]: 늘 같은 실패로 돌아옵니다(`CallRecordWork.kt:100`).
- 날짜 넘기기: 글자가 늦게 바뀝니다.

**원인 D: 시스템이 아무 창도 띄우지 않는 버튼. [근거]**
- [알림 허용하기]는 두 번 거절한 뒤 아무 반응이 없습니다(`HomeActivity.kt:171`).

**원인 E: 누른 뒤 화면이 엉뚱한 곳으로 갑니다. [근거]**
- 설정이 맨 위로 튑니다. 상세에서 돌아오면 목록이 맨 위로 튑니다.
- 탭을 눌렀는데 지난번 상세가 나옵니다(REORDER_TO_FRONT와 onNewIntent 없음).
- 알림으로 연 뒤에는 뒤로 가기가 순환합니다.

**우선 고칠 순서:**
1. 탭을 다시 누르면 목록이나 맨 위로 가게 합니다(2번). 30분 안에 끝나는 일입니다.
2. [다 됐어요]를 누르는 즉시 반응하고 두 번 누름을 막습니다(4번).
3. 화면마다 스토어를 한 번만 열고, 핸들 하나를 앱이 살아 있는 동안 유지합니다(1번 ①).
4. 알림은 TaskStackBuilder로 열고, 홈에서 뒤로를 누르면 앱을 끝냅니다(3번).
5. 설정의 스크롤과 메일 입력을 지킵니다(7, 8번).
6. 모든 화면에 "불러오는 중"을 표시합니다.

## 4. 50대 실사용 관점의 활용성 개선 제안 (우선순위 순)

1. **"처리 중" 표시를 모든 동작에 붙입니다.** 버튼을 누르면 즉시 꺼지고 글자가 "저장하는 중이에요"로 바뀌게 합니다. 눌렀는지 모르는 것이 "버그가 많다"는 인상의 첫 번째 원인입니다.
2. **현재 탭을 다시 누르면 목록과 맨 위로 가게 합니다.** 50대 사용자가 길을 잃었을 때 가장 먼저 누르는 곳이 그 탭입니다.
3. **통화 직후의 통화를 "정리 준비 중"으로 보여 줍니다(6번).** 방금 한 통화가 "녹음 없음"으로 나오면 앱을 믿지 못하게 됩니다.
4. **홈 숫자를 통화 탭과 같은 기준으로 셉니다(18번).** 두 화면의 숫자가 다르면 "앱이 틀렸다"고 느낍니다.
5. **아침 알림에서 바로 끝낼 수 있게 알림에 [다 됐어요] 동작 버튼을 둡니다.** 첫 항목에 Notification action을 달고 BroadcastReceiver로 `completeItem`을 부릅니다. "아침에 알림만 보고 끝내기"가 실제로 가능해집니다. 지금은 앱을 열어야만 완료할 수 있습니다.
6. **알림 허용과 권한이 막혔을 때 시스템 설정으로 바로 가는 버튼을 둡니다(13번).** 설정을 만지기 싫어하는 사용자도 한 번 눌러 해결할 수 있습니다.
7. **설정에서 스크롤 위치와 입력 중인 내용을 지킵니다(7, 8번).** 메일 연결은 다른 앱을 오가야 하는 유일한 작업이라, 입력이 지워지면 포기하게 됩니다.
8. **누를 수 없는 행은 누를 수 있어 보이지 않게 합니다(14번).** 직접 적은 일에는 리플을 없앱니다. 누를 때마다 오류 토스트가 뜨는 것이 "고장"으로 읽힙니다.
9. **실패한 통화의 이유를 쉬운 말로 알려 주고 소용없는 버튼을 없앱니다(10번).** "말소리를 찾지 못했어요"면 사용자가 더 할 일이 없다는 것을 바로 압니다.
10. **신호등 줄을 누르면 해당 설정으로 이동하게 하고 "위/아래" 안내를 바로잡습니다(24번).** 주황 불을 보고 무엇을 할지 찾는 단계가 하나 줄어듭니다.

## 6. 확인하지 못한 것 (에뮬레이터 없이 코드만 본 한계)

- **1번의 실제 시간.** DB 크기(수 MB)에 따라 열기, 스냅샷, 암호화가 몇 백 ms인지 몇 초인지는 실기기 계측(`System.nanoTime` 로그나 Perfetto)이 필요합니다. 홈 `read()` 앞뒤와 `ProtectedDatabase.State` 생성자, `transaction`에 시간 로그를 넣어 재 볼 것을 권합니다.
- **키보드 인셋.** targetSdk 36에서 edge-to-edge일 때 키보드가 설정의 메일 칸과 시트의 입력 칸을 가리는지는 확인하지 못했습니다. `systemWindowInsetBottom`에 IME가 들어가는지는 기기마다 다를 수 있습니다.
- **TodayCalls 화살표 아이콘의 정렬.** 글자 없는 Button에 왼쪽 드로어블만 있어 아이콘이 가운데가 아닐 수 있습니다(테마 패딩에 따라 다름).
- 글자 1.3배와 320dp에서 날짜 넘기기 글자, 큰 숫자 "120건"의 잘림.
- 삼성 One UI에서의 동작: 알림 권한 두 번 거절 뒤의 동작, "제한된 설정" 메뉴 이름(⋮)이 안내 문구와 같은지.
- 업데이트 무인 설치(`USER_ACTION_NOT_REQUIRED`) 뒤 앱이 다시 열리는지, 확인 창을 닫았을 때 홈 표시.
- WorkManager 주기 작업을 홈에 들어올 때마다 다시 등록(UPDATE)하는 것이 일정에 영향을 주는지.
- 실제 화면 미감(스크린샷 비교). `SheetShotsTest`의 결과 이미지는 보지 않았습니다.

# v3.3 자막 정확도 개선 협의안 (Fable 초안 + Opus 검토 반영, 2026-11-05 23:40)

> 대상: DESIGN_V4 3절(v3.3) 묶음 r13-2를 고쳐 쓸 Opus 세션. 코드 기준 `feature/r12-v31-r6`(e819f69), 실측 기준 ieum-inbox 11/5 23:12 하트비트(폰 v3.1, 빌드 1040).

## 0. 결론 한 줄

**지금 자막 문제의 1순위는 모델 정확도가 아니라 "긴 통화가 자막을 끝까지 통과하지 못하는 것"이다.** 우편함에 올라온 통화 자막 35건 중 가장 긴 통화가 99초이고, 11/4~11/5 48시간의 100초 넘는 업무 통화 27건은 모두 기록이 없다(대기 32건, 가장 오래된 대기 10/31, 누적 실패 8). "꽤 길게 통화했는데 한 문장"은 이 경로(대기·중지·실패)로 설명되는 쪽이 가장 유력하다. 그래서 v3.3 r13-2는 **① 커버리지(긴 통화 완주) → ② 실녹음 골든으로 측정 체계 → ③ 디코딩·프롬프트 A/B** 순으로 간다.

## 4. DESIGN_V4 3절과 충돌·수정할 곳

1. **파일 소유**: 이 안은 `CallTranscriptionStore.kt`, `ieum_whisper.cpp`, `PipelineAudio*`, `PhoneStatus.kt`를 고치므로 r13-2 소유 목록에 넣어야 함. A7은 r13-1이 가진 `ClaudeCallAnalyzer.kt`를 건드리지 말고 `hourly.md`(v7)에만.

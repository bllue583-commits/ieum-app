## B. 잘된 것
1. **결과 받기 시각이 루틴 실행 시각을 따라갑니다.** `ResultChain`(`pipeline/CallRecordWork.kt:467-595`)은 루틴이 자가 보고에 적은 cron을 읽어 실행 뒤 +3·+8·+15분에 받고, 24시간 상한이 있습니다. 결과 폴더·장부·버전 파일은 ETag로 읽어(`InboxETags`, `:603-645`) 바뀌지 않았으면 비용이 없습니다.
2. **자막 대기열의 멈춤 방지가 정교합니다.** 진척 있는 중지는 무해 처리(`CallTranscriptionRunner.kt:267`), 6분 뒤 새 녹음 안 집기(`:225`), 네이티브 기한 초과 시 조각 반으로 쪼개기(`:184,249`), 2분 조각 저장과 이어 하기, 대기열 순서(`CallTranscriptionStore.kt:127-142`)가 갖춰져 있습니다.
3. **벨이 울릴 때 큰 DB를 열지 않습니다.** 판정은 카드 파일의 blocked 표와 통화당 설정 스냅숏만 쓰고, 읽기에 실패하면 개인 번호로 쳐서 카드를 띄우지 않습니다(`pipeline/call/CallSession.kt:231-239`, `ContactCards.kt:195-237`).
4. **요청 본문 가리기를 한 곳에 모았습니다.** 메일 주소 → 전화번호(유선 포함) → 긴 숫자·계좌 순으로 가리고, 날짜는 남깁니다(`ClaudeCallAnalyzer.kt:199-221,333-334`). 메일은 보낸 사람 이름만 보냅니다(`MessageWork.kt:150-156`).
5. **보호 DB가 스스로 복구하고 상태를 알립니다.** 남은 `.new`/`.bak`를 판정해 복구하고(`ProtectedDatabase.java:196-223`), 저장소는 프로세스당 하나만 열며(`IeumApplication.kt:49-63`), 메인 스레드에서 열면 막습니다(`CallRecordStore.kt:1440`). 하트비트에는 `dbPercent`·`dbOpenMs`가 올라갑니다.

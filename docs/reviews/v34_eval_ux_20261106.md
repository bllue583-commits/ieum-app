# 이음 v3.4(1045) 제품·UX 평가 (읽기 전용, 11/6)

이번 평가는 문서, 화면 코드, 알림 코드, 카드 코드와 우편함에서 읽어도 되는 파일(`status/phone.json`, `last-run*.json`, `app/version.json`, `routines/`)만 근거로 삼았습니다. 화면 캡처가 없어서 레이아웃은 코드를 읽고 재구성했습니다. 파일은 하나도 바꾸지 않았습니다.

## A. 점수 (10점 만점)

| 항목 | 점수 | 한 줄 근거 |
|---|---|---|
| 처음 설정 | 6 | 한 번에 한 단계씩 보여 주고, 각 단계에 이유와 버튼 하나가 있어 잘 짜여 있습니다. 하지만 첫 실행 때 주황 신호등 4~5줄이 설정 단계보다 위에 나오고, 단계는 9개입니다. 핵심 기능인 카드는 "선택" 단계로 밀려 있습니다. |

## B. 잘된 것

1. **11/5 UI 지적 31건 중 약 27건이 닫혔습니다.** Activity가 하나로 통일되었고, 현재 탭을 다시 누르면 목록 맨 위로 갑니다(`CallsScreen.kt` `reselect()`). [다 됐어요]는 누르는 즉시 흐려지고 두 번 누름을 막습니다(`TaskActions.kt` `inFlight`). 설정 스크롤과 메일 입력이 유지되고, 바쁜 버튼은 "연결하는 중이에요"처럼 자기 상태를 말합니다. 측정값도 `homeReadMs` 40ms입니다.
2. **통화 직후 상태를 솔직하게 말합니다.** "녹음을 찾는 중이에요", "녹음을 글자로 바꾸는 중이에요", "녹음 없음"으로 나뉘고, 말소리가 없는 녹음은 "녹음에서 말소리를 찾지 못했어요"라고 하며 다시 정리하기 버튼을 감춥니다(`CallsScreen.kt:28-29,60-80`).
3. **카드 글 알고리즘이 3초 안에 읽히도록 짜였습니다.** 순서는 기한 → 확인 필요 → 14일 안의 요약 → 진행 중인 일 → thin("3일 전 통화, 30일간 5번")입니다. 첫 줄은 36자, 나머지 줄은 14자이고, 띄어쓰기에서 자르며 말줄임표가 없습니다. 전화번호만 가리고, 카드가 높이 한도를 넘으면 아래 줄부터 통째로 뺍니다(`CallCardView.kt:62-81,136-176,302-311`). 위치는 높이 34% 이하, 아래 끝 72% 이하이고 기본 위치는 38%입니다(`CallCardOverlay.kt:63-75`).
4. **처음 설정이 막혔을 때 출구가 있습니다.** 알림을 두 번 거절했으면 알림 설정을 열어 주고(`NotifyAsk`), 제한된 설정에 막혔으면 앱 정보 안내를 띄웁니다(`HomeScreen.kt:435`). 선택 단계에는 [나중에 할게요]가 있고, 다음 단계에 왜 필요한지 한 문장이 붙습니다(`SettingsScreen.kt:494-519`).
5. **화면 규칙을 시험으로 강제합니다.** `tools/check_ui_rules.py`가 가운데 점, 말줄임, 빨간색, 영어 상태값을 막고 `ui_min_sp` 태그로 18sp를 검사합니다. 다크 팔레트의 대비는 충분합니다(SUBTLE 7.3, AMBER 9.3). 아침 알림 잠금 화면 대체 글은 "잠금을 풀면 내용이 보여요"입니다.

# 이음 채점표 (v1, 2026-11-10 등록)

> "잘 됐다"를 사람이나 AI의 느낌이 아니라 **코드가 원시 데이터에서 계산한 값**으로 판정하기 위한 문서다. 문턱은 재기 전에 등록했고(`tools/inbox/scorecard.json`), 채점은 `tools/inbox/score.py`가 한다. 점수는 통과한 항목 수, 10점 만점. v4.0의 목표는 이 표의 10/10이다.

## 규칙

1. **문턱은 미리 등록한다.** 바꾸려면 `scorecard.json`의 `version`을 올리고 이 문서 맨 아래 "변경 기록"에 날짜와 이유를 적는다. 점수를 올리려고 문턱을 낮추지 않는다.
2. **채점은 코드가 한다.** `python3 tools/inbox/score.py --inbox <ieum-inbox 경로>`. 읽는 것은 우편함의 git 이력(하트비트, 예약 작업 자가 보고, 보고서 머리 숫자, 통화 대조표의 시각·길이·상태 칸)뿐이고 출력은 숫자뿐이다.
3. **관측이 모자라면 통과가 아니다.** 날짜별 항목은 최근 평일 10일 중 9일 이상, 운영·쓰임은 14일을 본다. 하루 좋은 값으로 통과하지 않는다.
4. **누가 돌려도 같은 값.** 맥락 없는 새 세션이 저장소 둘만 받아 같은 점수를 내야 한다(11/10 재현 기록은 아래).
5. 사람 손이 필요한 값은 세 가지뿐이고 파일로 남긴다: 정답지 측정 결과 `status/gold.json`, 설문 `status/survey.json`(SUS 점수, "없어지면 매우 아쉽다", 배터리 화면 비중), 비밀 스캔 결과 `status/secrets-scan.json`.

## 시뮬레이션이 말하는 것 (설계의 근거)

`tools/sim/queue_sim.py`에 10/1~11/9 실제 통화 655건(연결 20초 이상, 개인 제외; 시각과 길이만)을 흘려 정책별로 계산했다. 평일 통화는 하루 중앙값 50분·평균 65분·상위 10% 128분·최대 168분이고, 3분 넘는 통화가 건수의 26%지만 **분량의 71%**다.

가장 나쁜 조건(03:30에 꽂는 밤만, 말소리 계수 1.0)으로 돌리면 v3.7은 포함률 74%·95% 넘는 날 41%로 떨어지고, 엔진 유지 0.8배는 포함률 100%·저녁 82%, 초벌 엔진 0.06배는 그대로 100%·100%다(배터리 5분).

**읽는 법:** ① 시각표와 순서만 고쳐도(v3.7) 평균은 94%까지 가지만 항목 1의 "10일 중 9일 95%"에는 못 미친다. ② 항목 1·2를 충전 습관과 무관하게 채우는 길은 **녹음 1분을 30초 이하에 바꾸는 엔진 + 하루 25~30분의 배터리 실행** 하나뿐이다. ③ "충전 중에만"을 켜 두면 엔진이 아무리 빨라도 저녁 약속(59%)은 못 지킨다.

모형의 한계: 밀린 분량 없이 시작하므로 지금의 지연(38시간)보다 낮게 나온다. 낮 충전 두 번(점심·저녁 1시간)은 11/9 하루의 관측을 매일로 가정했다. 밤 충전은 3밤의 관측을 돌려 썼다. 분석 루틴은 회차 시작 12분 뒤 폰에 적용된다고 봤다.

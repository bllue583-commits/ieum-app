# G01/G02 재현과 수정 기록

기준 제품은 `dc0c16b506065a22a12ffaccf3b267aeeacae1fa`, 작업 branch는 `integration/major-features-20261026`다. 설계 검토 `6869fbb1f90c395dadb2c15695da2491899f5f4a`의 [runtime 인수 계약](RUNTIME_ACCEPTANCE_20261026.md)을 읽고 문서 변경을 merge했다. 기존 로컬 기반 데모의 원기록·원 APK/실행 근거는 그대로 보존한다. main과 feature branch를 변경하지 않는다.

Activity 종료의 별도 정리 취소를 버튼 성공으로 세지 않았다. |

G02 `LocalReviewedMorningSyncProgressTest` 수정 전 실행은 4건 중 PASS1/FAIL3/SKIP0이다. 실패는 알려진 빈 창의 COMPLETE 부재, 새 창으로의 queue 진행 부재, 빈 창이 protected checkpoint/fault 경로에 도달하지 않는 것이다. UNKNOWN/실패/검토 대기를 완료로 승격하지 않는 대조 시험은 통과했다.

첫 테스트 구성에서 15분 재조회 대기 전에 큐를 읽은 오류가 있었고, 원결과를 보존한 채 monotonic elapsed와 runtime lease를 갱신해 다시 실행했다. 위 G02 수치는 보정 후 같은 제품 코드의 두 번째 실행이다. 두 실행의 실패 수를 고유 제품 반례 수로 합산하지 않는다.

원근거: `evidence/g01-before/{receipt.json,instrumentation.log,public-evidence/analysis-stop.json}`, `evidence/g02-before-{1,2}/`, `evidence/g02-before-fix-2.log`. 모델·개인 자료·실제 메시지 전송을 사용하는 G02 시험은 아니다. G01은 전용 합성 AOSP35 ARM64에서 공개 bundled WAV의 실제 JNI를 사용했다.

## 수정 내용과 경계

- `PublicAudioOperation` 하나가 현재 화면 작업 하나의 취소 대상을 소유한다. 기존 pilot은 UI에서 즉시 결속하고, 생성 전 중단은 기억했다가 늦게 생성된 pilot에 전달한다. 표준/미분류 작업과 통합 작업이 서로의 inactive pilot을 대신 취소하지 않는다. 닫기/파괴도 같은 현재 작업의 중단을 먼저 요청한다.
- 중단된 작업의 늦은 성공 응답으로 통합 단계를 자동 진행하거나 완료 안내를 하지 않는다. 이미 commit된 이력은 삭제하지 않는다. **CP08의 최종 admission 이후 강한 취소 전체를 해결했다고 주장하지 않는다.** 실제 기기 반례는 분석 실행 중 취소와 내용 검토 명령 직후의 조기 취소를 각각 시험한다.
- `LocalReviewedMorningSync`는 성공적으로 읽은 로컬 snapshot이 정확히 `NO_RECORDINGS`, 대상0/자료0이고 pending/unresolved가 없는 경우에도 기존 보호 checkpoint transaction을 수행한다. 실제 commit 후에만 COMPLETE/durable cursor를 반환한다. 같은 request/window/generation의 재조회는 원 receipt/cursor를 유지한다.
- `DailyReportInput.fullyReviewed`의 사용자 검토 의미는 바꾸지 않았다. 확인된 **로컬 DB 0건**과 전체 외부 수집 완료는 다르다. `MorningCoverage.PARTIAL`, 로컬 scope note, dry-run 배송은 유지한다. DB 부재는 UNAVAILABLE, source failure·수집 미확인·검토 대기는 checkpoint/cursor를 만들지 않는다.
- 기존 ACCEPTED 요청을 삭제하거나 새 창으로 바꿔 끼우지 않는다. 정상 빈 창 자체가 완료되므로 기존 큐 알고리즘이 다음 request ID/window로 진행할 수 있게 한다. G03의 취소된 날짜/오래된 generation/ACK/UNKNOWN 재개 정책은 변경하지 않았다.

## 수정 후 검증

- 최초 집중 회귀: 앱84 PASS/실패0/SKIP0. G02 실제 source/queue 4개, 취소 token 3개와 기존 미분류·저장·보고 회귀를 포함한다. 이후 최종 코드 전체 실행을 별도로 기록한다.
- 실제 수정 후 분석 중단은 `activeIntegrationCancelled=true`로 통과했다. 추가 내용 검토 시험에서 기존 pilot을 worker 시작 시점까지 token에 결속하지 않아 즉시 취소 확인이 지연되는 경합을 발견했다. 기존 pilot의 UI 선결속으로 보강했으며 이 중간 APK/실패 로그도 보존했다.
- 수정 후 기기 도구 최초 실행은 adb 서버 동시 기동으로 앱 시험 전에 boot timeout이 났다. 전용5055 서버를 먼저 순차 기동하도록 도구를 고쳤고 기존 실패 로그를 보존했다. 새 권한/인증/SDK 설치나 다른 포트의 기기에 우회 연결하지 않았다.
- 최종 APK의 분석/내용 검토 중단 UI 시험은 각각 `OK (1 test)`다. 두 경우 `activeIntegrationCancelled=true`; 분석 중단은 시작 JNI1 이후 새 전사 결과/사용자 검토/자동 결과0, 내용 검토 중단은 시작 JNI2 이후 사용자 검토 영수증/요약0을 실제 보호 DB에서 확인했다. 이 숫자는 각 새 read-only 합성 AVD의 초기 상태를 기준으로 한다.

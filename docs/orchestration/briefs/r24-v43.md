## 배경 (꼭 읽을 것: `docs/DESIGN_V8.md` 6-3, 6-4)

- 통화 카드(통화 화면 위에 겹쳐 그리는 창)는 삼성 Telecom의 `SamsungRestrictOverlayProcessor`가 막는다: 일반 전화가 걸려 있는 동안 "출처를 알 수 없는 앱"의 다른 앱 위에 표시 앱옵을 거부로 바꾸고 끝나면 되돌린다. 새로 설치한 뒤 6~15시간은 뜨다가 다시 막힌다(세 번 관찰: 11/19 18:41까지, 11/20 17:31까지). 우회하지 않는다.
- 막힌 동안에는 소리 없는 머리 알림(`CallCardOverlay.buildNotice`, 채널 `ieum.calls.card`, IMPORTANCE_HIGH)이 대신 뜬다 — 11/20~21 전부 실제로 떴다(`fallbackShown` = `fallback`, `fallbackMuted` 0). **지금 아내가 보는 통화 카드는 이 알림이다.** 스토어 배포(갤럭시 스토어 비공개 베타)는 따로 시도 중이고 될지 모른다.
- 배터리 예산(하루 20분)을 지키게 된 뒤(v4.2) 낮의 자막이 예산에서 멈춘다: 11/20 18:21에 지연 중앙값 144분·대기 13건, 11/21 17:38에 20분 도달. 화면 꺼짐 기준 약 4.5mAh/분(20분 ≈ 배터리의 2~3%). 사용자는 배터리가 괜찮다고 했다.
- 통화 기록과 연결 안 되는 녹음(`callLogMatch.last.length` 18) 중 17건이 60초 미만 녹음이고 통화 기록의 통화는 120초 넘게 더 길다. 하루 한 건꼴로 새로 생긴다.

## r24-1 알림을 정식 통화 카드로

목표: 겹쳐 그리기가 막힌 통화에서도 아내가 "이 사람과 무슨 일이 있었지"를 통화 화면에서 한눈에 떠올린다.

1. 지금 동작을 코드로 먼저 확인해 보고에 적는다: 권한이 통화 시작부터 거부일 때(`d0`) 알림이 뜨기까지 몇 ms인지(다시 붙이기 대기 0.6초·2초·`RETRY_HIDDEN_MS`를 기다리는지), 알림이 통화가 끝나면 지워지는지, 잠금 화면·화면 꺼짐에서 무엇이 보이는지, 눌렀을 때 어디로 가는지.
2. 거부가 확인되면(통화 시작 때 `canDrawOverlays` 거짓) **기다리지 않고 바로 알림**을 띄운다. 다시 붙이기는 권한이 있는데 붙이기가 실패한 경우에만 남긴다.
3. 알림의 내용과 모양을 카드와 같은 정보 위계로 다듬는다(`CallCardView.Content`를 그대로 쓰되 알림에 맞게):
   - 제목: 이름 · 업체(있으면). 접힌 한 줄: 가장 중요한 열린 일 하나 또는 지난 통화 한 줄.
   - 펼친 모양(BigText 또는 InboxStyle 중 삼성 One UI에서 더 읽기 좋은 쪽 — 줄 수 제한을 확인): 열린 체크할 일 최대 3개(중요한 것부터), 지난 통화 한 줄과 날짜. 숫자·금액은 카드에서 쓰는 규칙 그대로.
   - 통화 화면에서 머리 알림으로 떠야 한다: 소리·진동 없음, `CATEGORY_CALL`은 유지할지 판단(삼성이 통화 중 통화 분류 알림을 다르게 다루는지 문서·코드 주석에서 확인, 모르면 그대로). 통화가 끝나면 지운다(카드의 "끝난 뒤 3초" 규칙과 같게).
   - 잠금 화면: 지금의 공개 판(이름과 한 줄, 설정 "잠금 화면에서도 이름과 한 줄 보기")을 그대로.
   - 누르면: 그 사람의 화면(이미 있는 진입점이 있으면 그것, 없으면 챙길 일 화면)으로. 통화를 끊지 않는다.
   - 색·아이콘: 앱의 강조색, 작은 아이콘은 지금 것. 큰 아이콘은 쓰지 않는다(사진 없음).
4. 카드가 그려질 수 있는 통화(설치 직후)에서는 지금처럼 카드를 그리고 알림은 서비스 알림 하나만 — 두 번 보이지 않게.
5. 기록: `callCard.today`에 `noticeMs`(통화 시작부터 알림까지의 중앙값 ms), `noticeTaps`(알림을 눌러 앱으로 들어온 수). 숫자만.
6. 설정 화면의 통화 카드 설명 문구가 "통화 화면 위에 카드"만 말하면, 알림으로 보일 수 있음을 한 줄로(짧게, UI 문구 규칙 `tools/check_ui_rules.py`를 따른다).
7. 시험: 거부일 때 바로 알림 / 허용일 때 카드 / 통화 끝에 지움 / 내용 위계(일 3개 넘으면 3개) / 잠금 화면 공개 판 / 누름 진입.

하지 않는 것: 전체 화면 알림(full-screen intent), 접근성 서비스, 다시 설치로 돌아가기, 통화 화면을 덮는 다른 수단.

## r24-4 연결 실패: 60초 미만으로 저장된 녹음 길이

- 가설: 녹음 파일을 통화가 끝나기 전(파일이 자라는 중)에 발견해 그때의 길이를 저장하고 다시 재지 않는다. **먼저 코드로 확인**(발견 시점, 길이를 읽는 곳, 다시 읽는 곳이 있는지, 자막을 만들 때 쓰는 길이는 어디서 오는지). 가설이 틀리면 고치지 말고 확인한 사실과 다른 가설을 보고.
- 맞으면: 자막을 만들기 시작할 때(또는 끝낼 때) 실제 길이로 저장값을 바로잡고, 바뀌었으면 통화 기록 연결을 다시 시도한다. 이미 `length`로 남은 묵은 기록도 다음 패스에서 길이를 다시 재서(파일이 남아 있으면) 한 번 다시 시도한다 — 파일이 없으면 그대로 둔다.
- 하트비트 `callLogMatch.last.relinked`(길이를 바로잡아 연결된 수). 시험.
- 발견 자체가 너무 이르다면(통화 중 파일을 자막 대기열에 넣는다면) 그것이 다른 문제를 만드는지도 확인해 보고에 적는다(자막이 잘리지는 않는지).

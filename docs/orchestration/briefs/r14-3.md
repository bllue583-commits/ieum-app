# r14-3 스스로 지키는 루틴 (브랜치 `feature/r14-v34-r3`, 기준 `feature/r14-v34`)

## 기준 문서
- 공통 지침: `docs/orchestration/worker-brief.md`(기준 브랜치만 `feature/r14-v34`).
- 설계: **DESIGN_V4 4.3절 1~5·7·8**, 4.5절 루틴 기준.
  - 4.3-6(30분 간격)은 하지 않는다.
- 검토 원문: `docs/reviews/v34_review_20261106.md`.

## 맡는 범위
- **파일 소유:** 4절 머리 "파일 소유"의 r14-3 줄 그대로.
  - ieum-inbox 쪽 워크플로 삭제는 오케스트레이터가 한다.
  - 당신은 앱 저장소의 `tools/inbox/watchdog.py`, `tools/inbox/watchdog.yml` 사본까지만 고친다.
- **같은 시간에 고치는 작업자:** r14-1이 `CallSession.kt`, `CallStateReceiver.kt`, `CallCardService.kt`, `OutgoingCallService.kt`, `CardStats.kt`, `ContactCards.kt`, `PhoneStatus.kt`, 설정·홈의 역할 단계를 고친다. 이 파일들은 건드리지 않는다.
- **하트비트:** 당신은 설정 키에 값만 쓴다. 하트비트에 올리는 것은 r14-1이 한다.
  - 쓸 키(키 커밋에 이미 있음): `ROUTINE_ENDED_MS`, `ROUTINE_CRONS`, `UPDATE_ERROR_CODE`, `MAIL_ERROR_CODES`, `RECORD_TIME`.
  - `latency.outliers`는 기존 `LATENCY` JSON 안에 키로 더한다.

## 지시문 v8 (hourly.md, tidy.md)
- **버전 맞추기:** `RoutineDocTest`가 hourly 문서 버전과 `ClaudeCallAnalyzer.PROMPT_VERSION`을 맞춰 보는지 확인한다. 맞춰 보면 `PROMPT_VERSION`을 8로 올리고 SYSTEM과 SCHEMA를 문서와 같게 둔다.
  - 분석 규칙이 바뀌지 않으면 결과 형식은 7과 같다. 지시문은 7을 과도기 요청으로 받는다.
- **tidy 버전:** tidy를 올리면 `version.json`의 tidyVersion을 만드는 곳(`tools/release/version_fields.py` 또는 그 원본 상수)도 함께 맞춘다.
- **v7 위에서 고친다:** v3.3에서 루틴 문서 v7에 넣은 두 규칙을 지우지 않는다.
  - 합치기 장부 수정 규칙(mergePeople/unmergePeople, keepApart).
  - mergeCandidates 형식.
- **자가 보고 파일:** `status/last-run-hourly.json`, `status/last-run-tidy.json`으로 나눈다.
  - 워치독과 폰(결과 받기)은 새 파일을 먼저 읽고, 없으면 옛 `status/last-run.json`을 읽는다(과도기).
- **워치독 실행:** 루틴 마지막 단계에서 `python3 tools/watchdog.py`를 돌리고, 이슈는 REST `gh api`로 연다.
  - ieum-inbox의 `tools/watchdog.py`는 앱 저장소의 `tools/inbox/watchdog.py`를 오케스트레이터가 복사해 둔 것이다.
  - 실행 인자와 출력 형식은 지금 `watchdog.yml`이 하는 것과 같게 한다.

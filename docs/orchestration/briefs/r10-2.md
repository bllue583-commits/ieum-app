# r10-2 통화별 알림 (v2.9)

공통 지침 `docs/orchestration/worker-brief.md`를 먼저 읽고 따르세요. 브랜치 이름: `feature/r10-v29-r2`. 기준은 `feature/r10-v29`(v2.8 완성본).

설계: `docs/DESIGN_V3.md` 6.2절 **r10-2** 전부. 통화가 끝나면 "김민수 대표와 통화를 정리하고 있어요" 알림 1건 → 결과가 오면 같은 알림을 "정리됐어요" + 요약 첫 문장 + 체크할 일 1줄로 → 6시간 안에 결과가 없으면 "정리가 늦어지고 있어요, 저녁 보고에 넣어 드릴게요". 알림 액션 [메모 남기기](RemoteInput 한 줄 → `addUserItem(title, company, source=user, record 연결)`).

## 담당 파일
- `pipeline/CallFollowupNotice.kt`(신설): 채널 `ieum.calls.followup` "이음 통화 정리"(소리·진동 없음, 잠금 화면에는 "통화 정리 중"만). 공개 함수(**이 이름 그대로**):
  - `onCallEnded(context, end: CallSession.CallEnd)` — r10-1의 `CallSession`이 부릅니다(아직 없으면 같은 모양의 데이터 클래스를 받는 걸로 작성하고 보고서에 적기). 업무 상대로 확인된 통화(상대 카드 `ContactCards.get(phoneKey)`가 있거나 전화부 이름이 있음)만 알림. 개인·제외 번호는 아무것도 안 함.
  - `onResult(context, recordId)` — `CallRecordStore.applyAnalysis` 끝(또는 `CallRecordWork`의 결과 반영 뒤)에서 한 줄로 부릅니다. 같은 알림을 "정리됐어요"로 갱신(BigText), 누르면 통화 상세(`MainActivity.intent(..., callId)`).
  - `sweep(context, now)` — `CallRecordWork` 매시간 틱 끝에서 한 줄: 6시간 넘은 것은 "늦어지고 있어요"로, 저녁 보고가 나간 뒤에는 그날 통화별 알림 삭제(`CallDigestWork` 저녁 보고 뒤 한 줄).
  - `NotificationActions`(v2.7 r8-6, `NotificationActionReceiver`, 액션 `kr.callbrief.action.TASK_DONE`)에 액션 `kr.callbrief.action.CALL_MEMO`(RemoteInput key `memo`, extra `recordId`)를 더해 같은 수신기에서 처리.
- 알림 id는 기록 키 기준(`("followup"+recordId).hashCode()`), 통화가 끝났지만 기록이 아직 없을 때는 `phoneKey+endedMs` 임시 키 → 기록이 생기면(`onResult` 또는 자막 작업이 기록을 만들 때) 같은 알림으로 이어 붙이기(설정에 임시 키 → recordId 매핑 또는 `call_records` 시각 ±2분 대조).
- 설정 "정리" 묶음(`screens/SettingsScreen.kt`)에 스위치 "통화마다 알림"(기본 켬, 키 `PipelineSettingsKeys.FOLLOWUP_NOTICE`) — 그 파일은 스위치 한 줄 추가만.
- 다른 묶음: r10-1이 `pipeline/call/*`, 매니페스트 권한·수신기, 홈 처음 설정 단계; r10-3이 `CallRecordWork`의 결과 체인(`ieum.calls.results`)과 루틴 문서. `CallRecordWork`에는 `sweep`/`onResult` 호출 한 줄씩만.

# r9-1 저장소 기반 (v2.8)

공통 지침 `docs/orchestration/worker-brief.md`를 먼저 읽고 따르세요. 브랜치 이름: `feature/r9-v28-r1`. 기준은 현재 worktree HEAD(`feature/r9-v28` = v2.7 완성본 + `core/PhoneKey.kt`).

설계: `docs/DESIGN_V3.md` 5.1절 **r9-1** 전부(단, 2번 "프로세스 수명 동안 한 번만 연다"는 v2.7 r8-1이 이미 했습니다 — `IeumApplication.store(context)`. 남은 것은 **`CallRecordStore` 메인 스레드 검사**와 아직 `CallRecordStore(...).use{}`로 여는 WorkManager 작업들을 프로세스 저장소로 바꾸는 것뿐). 검증 보고서 `docs/reviews/20261105_data.md`의 문제 1·2·3·4·13·14·22를 닫습니다.

## 담당 파일
- `android/core/.../PrivacyRules.kt`(normalizePhone 호출처 정리), `android/core/.../PhoneKey.kt`(이미 있음, 바꿀 일이 있으면 테스트와 함께)
- `pipeline/CallRecordStore.kt`(counterpartKey → PhoneKey, MIGRATION_VERSION 올리고 people_phones·people.phone_key·call_records.counterpart_key·call_log.number_key·personal_numbers 재계산, 같은 키 사람 합치기(별칭·call_links·people_phones 이동), 인덱스, issue_companies 채우기, 메인 스레드 검사)
- `pipeline/MessageWork.kt`(`phoneKey` → PhoneKey.of), `pipeline/FirstPass.kt`(readCallLog), `CallLogReport`, `pipeline/CallTranscriptionRunner.kt`의 `counterpart()`
- `call-core-android/.../ProtectedDatabase.java`(.new/.bak 복구 규칙, 결과를 설정 `DB_RECOVERY_LAST`로 → 하트비트 `dbRecovery`는 이미 있음)
- `pipeline/CallRecordWork.kt`(`runInbox` 한 기록 처리를 `port.transaction{}` 하나로)
- `pipeline/StatusLights.kt`·`SelfCheckNotices.kt`(저장 공간 % = `max(바이트%, 행%)`, 바이트는 `ProtectedDatabase.file(context,DATABASE).length()`)
- 관련 테스트. **다른 묶음**: r9-2가 `pipeline/ContactCards.kt`(신설)와 `CallRecordStore`의 몇 메서드 끝에 한 줄씩 훅을, r9-3이 `screens/PersonScreen.kt`(신설)·`MainActivity.kt`·`screens/*.kt`를 고칩니다. `CallRecordStore`는 겹치니 **새 함수는 클래스 끝에**, 기존 함수는 꼭 필요한 줄만 고치세요.

## 할 일(설계 5.1 그대로, 요약)
1. `PhoneKey.of`를 모든 호출처가 씀(`counterpartKey`는 번호면 PhoneKey.of, 메일이면 소문자, 그 밖은 이름). 마이그레이션(`MIGRATION_VERSION`+1)으로 저장된 키 재계산·사람 합치기. 테스트: 같은 번호의 두 표기가 한 사람으로 합쳐지고 별칭·연결이 따라옴.
2. `CallRecordStore`에 메인 스레드 검사(`Looper.getMainLooper().isCurrentThread`면 IllegalStateException; Robolectric 시험은 메인 스레드에서 도니 `CallRecordStore.MAIN_THREAD_CHECK` 같은 스위치로 시험에서 끌 수 있게). WorkManager 작업의 `use{}`를 `IeumApplication.store`로.
3. `runInbox` 한 기록 처리 트랜잭션 하나(markSent/setState/setReceived/editSent).
4. 보호 파일 복구: `.new`는 AEAD 검증 통과 + cipherHash가 main과 다르면 승격, 아니면 삭제. `.bak`은 main 검증 실패 때만 승격. 결과 `DB_RECOVERY_LAST`. Robolectric `.new` 잔존 시나리오 테스트.
5. 저장 공간 % = `max(바이트%, 행%)`; 80% 알림(B4)이 실제로 뜨는 단위 테스트.
6. 인덱스: `call_links(person_id)`, `call_links(company_id)`, `task_companies(company_id)`, `call_log(number_key,start_ms)`, `call_records(counterpart_key)`, `workflow_items(status,kind)`, `people_phones(person_id)`.
7. `issue_companies(issue_id,company_id)`를 `applyLedger`에서 채움.

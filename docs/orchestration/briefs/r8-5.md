## 1단계가 만들어 둔 것(이걸 씁니다)
- 화면은 `MainActivity` 하나, 각 화면은 `AppScreen(a:MainActivity)` 하위 클래스(`enter/leave/reselect/back/save/restore`, `live()`). 이동은 `a.openCall(recordId,dayMs)`, `a.openCompany(name)`, `a.switchTo(screen)`, 스크롤 복원은 `a.putBack(y)`/`CallUi.scrollTo`. 테스트는 `launchMain(Screen.TASKS)` 등(`MainLaunch.kt`).
- 저장소: `kr.callbrief.IeumApplication.store(context)`가 프로세스 수명 `CallRecordStore`를 줍니다. **`CallRecordStore(...).use{}`로 새로 열지 않습니다**(설정 `refresh()`는 r8-1이 이미 한 번 열기로 바꿈).
- r8-3 부품: `CallUi.once`, `busy/idle`(동작별), `loading`, `retryCard`, `button(busyText=)`, `sheetDialog(validate=)`(입력 칸 있으면 키보드 자동), `signalRow(onPress)`, `StatusLights.Light.target`(신호등 줄 → 묶음 스크롤, tag "group_"+이름), `TaskActions`의 즉시 반응·`inFlight`·실패 복원, `ScreenParts.searchBox(Context)`.

## 할 일(설계 4.2 r8-5 그대로, 요약)
1. 체크 행: 통화에서 온 항목만 누를 수 있음(`OpenItem.recordingId`로 바로 찾기 → `a.openCall`), 직접 적은 항목·새벽 팔로업은 눌림 표시 없음. 행 순서 G3(업체 배지 → 제목 → META "김민수 님, 오늘 요청" → ai_note → [다 됐어요]), META의 사람 이름을 누르면 그 통화. 열린 일 30개 먼저 그리고 나머지는 나눠 그리기.
2. 업체 상세: 머리에 "업체 이름 고치기" 글자 링크(사람 이름 고치기와 같은 시트, `validate`로 빈 이름 막기, `company_aliases`에 옛 이름). 목록으로 돌아올 때 들고 있던 목록으로 즉시 그린 뒤 백그라운드 갱신.
3. 설정: `render`가 스크롤 위치 저장·복원. 스위치·슬라이더는 다시 그리지 않고 글자만 고침. 메일 주소·비밀번호 입력은 화면 필드에 담아 다시 그릴 때 넣음. 서비스 버튼은 버튼 색·안내·host 칸만 바꿈. busy는 동작별 플래그, 해당 버튼만 "연결하는 중이에요". 슬라이더 저장은 `onProgressChanged(fromUser)` 700ms 디바운스. 신호등 FAILED 수는 `EMPTY_TRANSCRIPT` 제외. 신호등 줄을 누르면 그 묶음으로 스크롤(`Light.target` 사용).
4. 읽기 실패 시 `retryCard`, 읽는 동안 `loading`. 모든 행·버튼은 `once`.

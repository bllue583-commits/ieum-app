# r9-2 상대 카드 저장소 (v2.8)

공통 지침 `docs/orchestration/worker-brief.md`를 먼저 읽고 따르세요. 브랜치 이름: `feature/r9-v28-r2`. 기준은 현재 worktree HEAD(`feature/r9-v28` = v2.7 완성본 + `core/PhoneKey.kt`).

설계: `docs/DESIGN_V3.md` 5.2절 **r9-2** 전부. 목적: v3.0의 통화 카드(오버레이)가 0.1초 안에 뜨도록 번호별 요약을 작은 별도 암호 파일에 미리 계산해 둔다. 검증 보고서 `docs/reviews/20261105_data.md` 6절 참고.

## 담당 파일
- `pipeline/ContactCards.kt`(신설): 별도 암호 파일 `contact-cards-v1.sealed`(같은 `ProtectedDatabase` 방식, `GeneralLocalStore.DATABASE`와 다른 파일 이름), 표 `contact_cards(phone_key PK, json, updated_ms)`. 카드 JSON v1은 설계 5.2 그대로(`people`, `company`, `lastCallMs`, `lastDirection`, `recent`×3, `openTasks`×5, `issues`×3, `texts`×2, `updatedMs`).
- `ContactCards.get(phoneKey)`: 메모리 `ConcurrentHashMap` → 카드 파일. `ContactCards.refresh(store, phoneKeys)`(바뀐 번호만 다시 계산), `rebuildAll(store)`, `preload(context)`(앱 시작과 매시간 틱 끝).
- 번호 키는 반드시 `kr.callbrief.core.PhoneKey.of`로(저장된 옛 키가 정규화 전일 수 있으니 카드를 만들 때 `PhoneKey.of(stored)`로 다시 계산). 개인 번호(`personal_numbers`)와 설정의 제외 번호는 카드를 만들지 않고 있던 카드는 지움.
- 훅: `CallRecordStore`의 `applyAnalysis`, `applyLedger`, `applyTidy`, `completeItem`, `undoDone`, `addUserItem`, `renamePerson`, `reconcileCallLog`, `forgetPersonal`와 문자·메일 저장 뒤에 **각각 한 줄** `ContactCards.touch(keys)`(바뀐 번호 모음; 실제 재계산은 IO에서 묶어서). r9-1이 같은 파일의 마이그레이션·인덱스·키 규칙을 고치고 있으니 `CallRecordStore`에서는 훅 한 줄과, 카드 계산에 필요한 읽기 쿼리를 **클래스 끝에** 더하는 것 이상은 하지 마세요.
- `IeumApplication.onCreate`에 preload 한 줄, `CallRecordWork`(매시간 틱) 끝에 preload 한 줄.
- 설정 화면의 [카드 다시 만들기] 버튼은 r9-3/다음 버전 몫 — 이 묶음은 `rebuildAll`만 제공.

## 목표와 시험

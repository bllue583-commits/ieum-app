## 1단계가 만들어 둔 것(이걸 씁니다)
- 화면은 `MainActivity` 하나, 각 화면은 `AppScreen(a:MainActivity)` 하위 클래스(`enter/leave/reselect/back/save/restore`, `live()`). 상세·화면 이동은 `a.openCall(recordId,dayMs)`, `a.openCompany(name)`, `a.switchTo(screen)`. 테스트는 `launchMain(Screen.HOME)`/`launchMain(Screen.CALLS,dayMs,callId)`(`MainLaunch.kt`).
- 저장소: `kr.callbrief.IeumApplication.store(context)`가 프로세스 수명 `CallRecordStore`를 줍니다. **`CallRecordStore(...).use{}`로 새로 열지 않습니다.** 홈 `read()`는 r8-1이 이미 한 번 열기로 바꿨습니다(`readOnce`, `HOME_READ_MS` 측정) — 그 구조를 유지하세요.
- r8-3 부품: `CallUi.once(view,action)`(600ms 두 번 누름 막기, 테스트에서는 `idleFor(700)`처럼 기다림), `CallUi.busy(button,"…하는 중이에요")`/`idle`, `CallUi.loading(column,"불러오는 중이에요")`, `CallUi.retryCard(column){}`, `button(...,busyText=)`, `sheetDialog(validate=)`, `CallUi.PAGE_CAPTION`.

## 할 일(설계 4.2 r8-4 그대로, 요약)
1. 홈 숫자 라벨 "오늘 통화 / 오늘 생긴 체크 / 남은 체크할 일". "오늘 통화"는 통화 탭과 같은 기준(기록+통화기록 줄). 메모 없으면 "오늘 통화 n건을 정리하고 있어요". 체크 목록 "먼저 볼 체크할 일": 오늘 요청+확인 요청 최대 5개, "외 n개 보기 ›"(누르면 체크 탭).
2. 통화 직후 상태: 받은·건 전화, 길이>0, 12시간 안, 폴더 연결 → "녹음을 글자로 바꾸는 중이에요"(`call_transcription_jobs` QUEUED/RUNNING ±2분이면 더 정확히). 업로드 뒤 "정리하고 있어요", 6시간 넘으면 "정리가 늦어지고 있어요".
3. 날짜 넘기기: 즉시 날짜 글자·화살표 교체 + "불러오는 중" → 읽기. 검색: `(record, haystack)` 미리 만들기, 250ms 디바운스, 상세에서 돌아오면 검색어 유지.
4. `EMPTY_TRANSCRIPT` 실패는 "녹음에서 말소리를 찾지 못했어요", [다시 정리하기] 없음. 그 밖의 실패에만 버튼.
5. [모델 받기] 모바일 데이터면 "Wi-Fi에 연결되면 받기 시작해요"를 단계 본문에, 받는 동안 1초마다 퍼센트.
6. 녹음 폴더 선택 결과 처리와 [지금 업데이트]의 SHA-256·세션 복사는 IO 스레드로, 버튼은 "확인하는 중이에요".
7. [알림 허용하기]: 두 번 거절 뒤 "알림 설정 열기"(`ACTION_APP_NOTIFICATION_SETTINGS`). 판정은 `areNotificationsEnabled()`까지.
8. 읽기 실패 시 `retryCard`, 읽는 동안 `loading`. 모든 행·버튼은 `once`.

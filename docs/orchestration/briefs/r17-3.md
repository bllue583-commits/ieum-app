# 묶음 r17-3: 계측과 채점용 표시 (v3.7, DESIGN_V7 3.3절)

공통 지침 `docs/orchestration/worker-brief.md`. 기준 `feature/r17-v37`(r17-0·r17-1·r17-2와 v3.6.1이 모두 합쳐진 상태), 자기 브랜치 `feature/r17-v37-r3`. 채점표는 `docs/SCORECARD.md`, 채점기는 `tools/inbox/score.py`(읽기만 — 키 이름을 여기에 맞춘다).

## 원칙
하트비트(`status/phone.json`)에는 **숫자와 코드만** 나간다. 이름·전화번호·통화 내용·자막은 절대 넣지 않는다. 벨 경로(통화 카드)와 화면 그리기에서 봉인 DB를 새로 열지 않는다. 계측 실패가 본 기능을 죽이지 않는다.

## 할 일
1. **지연 세 구간 + 그날 값(`CallRecordStore`의 진단부 1548~ 근처, `PhoneStatus`):** `latency`에 `segments{endToText, textToUpload, uploadToApplied}`(각 p50Min·p90Min; 재료 `created_ms`·`call_inbox_sent.sent_ms`·`received_ms`/`analyzed_ms`는 이미 있다)와 **`latency.day{p50Min, p90Min, n}`**(KST 오늘 끝난 통화만의 통화 끝→결과 적용; 채점기가 읽는다). 7일 넘는 값은 버리지 말고 `over7d` 건수로.
2. **통화별 추적 `trace[]`:** 최근 50통화의 단계별 시각(통화 끝, 녹음 발견, 자막 시작·끝, 업로드, 분석 결과 적용) — 각 통화는 `{endMin(KST 그날 0시부터 분), day, durS, foundS, textStartS, textEndS, uploadS, appliedS}`처럼 **통화 끝 기준 초 차이**로(없으면 null). 상대 정보·기록 id 없음. 하트비트 크기를 지키려면 50개 × 작은 객체.
3. **자막 창 통계 `transcription.window14{created, failed}`:** 최근 14일에 생긴 녹음(대기열에 들어온 것) 수와 그중 최종 FAILED인 **서로 다른** 녹음 수(영구 실패 포함 여부는 `failedPermanent`로 따로). 누적 카운터 `transcriptionFailed`는 그대로 둔다.
4. **보고 포함률 `report.coverage{yesterdayCalls, inReport, pending}`:** r17-2가 만든 `kr.callbrief.pipeline.report.ReportCoverage.snapshot(settings)`의 앞 세 값을 하트비트 `report` 블록에.
5. **사용 숫자 `use{today{…}, prev{…}}`:** 하루 단위 횟수만 — `opens`(앱 화면이 앞으로 온 횟수), `homeSec`(홈 체류 초 합), `taskDone`([다 됐어요] 누른 수: 앱·알림 모두), `notifTap`(이음 알림을 눌러 들어온 수), `cardExpand`(통화 카드 띠를 눌러 펼친 수 — 기존 `expanded`를 그대로 써도 된다), `kakaoOpen`(카톡 보고의 링크로 들어온 수). 자정(KST)에 today → prev. 저장은 봉인 설정의 작은 JSON 하나(새 키 "v3.7 r17-3" 블록), 화면·알림 경로에서 동기 암호화 쓰기가 잦아지지 않게 메모리에 모아 화면이 뒤로 갈 때·하트비트 때만 쓴다.
6. **DB 내역 `dbTables`:** 봉인 DB의 테이블별 행 수와 글자 길이 합 상위 8개(`{name, rows, chars}`), 하루 한 번만 계산(VaultPrune 때)해 설정에 남기고 하트비트는 그 값을 읽는다.
7. **못 이은 녹음 사유의 하루 값:** `callLogMatch.day{noCandidate, length, …}`(지금 `last`는 마지막 실행 것뿐).
8. **작업별 전력·CPU(가능한 범위):** 자막 실행 한 번이 끝날 때 `/proc/self/stat`의 utime+stime 차이(틱→ms), `BatteryManager.BATTERY_PROPERTY_CHARGE_COUNTER` 차이(µAh, 배터리 실행일 때만 의미), `/proc/self/cpuset`을 전력 원장(`PowerStats`)의 `today.cpuMs`·`today.batteryUah`에 더한다. `PowerText`가 내보낸다. Runner에 훅이 없으면 실행 시작·끝의 한 줄씩만 더한다.
9. **워치독(`tools/inbox/watchdog.py`·시험):** "아침 보고 포함률 < 80%가 평일 이틀 연속"(`report.coverage`), "`dbPercent` ≥ 70" 규칙 추가.
10. **남은 문구 세 곳(작게):** "끝나기까지 약 1시간 안"(`SettingsScreen` — 지키지 못할 약속, 시간 약속 없는 문장으로), 자가 진단의 "와이파이에 연결한 뒤"(`SelfCheckNotices` — 연결 종류 무관), 신호등의 "위 ○○ 묶음에서" 방향 글(`StatusLights` — 주황이면 신호등이 맨 위라 "아래"). 화면 글 규칙 준수.

## 담당 파일
`pipeline/PhoneStatus.kt`, `CallRecordStore.kt`의 진단부(1548~)와 필요한 읽기 함수, `StatusLights.kt`(문구 한 곳), `SettingsScreen.kt`(문구 한 곳), `SelfCheckNotices.kt`(문구 한 곳), `MainActivity.kt`·`TaskActions.kt`·`NotificationActions.kt`(사용 횟수 한 줄씩), `VaultPruneWork.kt`(dbTables), `PowerPolicy.kt`·`PowerText.kt`·`CallTranscriptionRunner.kt`(8번의 최소 추가만), `CallPorts.kt`(자기 키만), `tools/inbox/watchdog.py`·`test_watchdog.py`, 관련 시험(`PhoneStatusTest` 등). 만지지 말 것: `pipeline/call/*`(카드 통계는 v3.6.1에서 끝남 — `expanded`를 읽기만), `pipeline/report/*`(읽기만), `docs/routines/*`, `tools/inbox/score.py`.

## 시험
하트비트 JSON에 이름·번호 모양이 없음(숫자 6자리 이상 연속·한글 이름 없음)을 검사하는 시험, `latency.day`·`segments` 계산, `window14`가 재큐된 녹음을 한 번만 셈, 사용 횟수가 자정에 넘어감, `dbTables` 상위 8개, 워치독 두 규칙, 하트비트 크기가 크게 늘지 않음(예: 20KB 이하).

# r14-1 모든 전화에 카드 (브랜치 `feature/r14-v34-r1`, 기준 `feature/r14-v34`)

## 기준 문서
- 공통 지침: `docs/orchestration/worker-brief.md`(기준 브랜치만 `feature/r14-v34`).
- 설계: **DESIGN_V4 4절 머리, 4.1절 1~6, 4.5절**.
- 검토 원문: `docs/reviews/v34_review_20261106.md`.

## 맡는 범위
- **파일 소유:** 4절 머리 "파일 소유"의 r14-1 줄 그대로.
- **같은 시간에 고치는 작업자:** r14-3이 `CallRecordWork.kt`, `CallUpdate.kt`, `CallRecordStore.kt`, `ClaudeCallAnalyzer.kt`, `MessageWork.kt`, 루틴 문서, 워치독을 고친다. 이 파일들은 건드리지 않는다.
- **r14-2:** 당신 브랜치에서 이어서 시작한다. 그래서 카드 화면 파일(`CallCardOverlay.kt`, `CallCardView.kt`, `CallFollowupNotice.kt`, `StatusLights.kt`)은 고치지 않는다. 다만 4.1-6 카드 JSON v2의 새 필드는 `ContactCards`에서 채운다.

## 키 커밋 (이미 있음)
- `PipelineSettingsKeys`의 v3.4 묶음: `ROUTINE_ENDED_MS`, `ROUTINE_CRONS`, `UPDATE_ERROR_CODE`, `MAIL_ERROR_CODES`, `RECORD_TIME`, `ROLE_OFFER_SEEN`.
- 이 키들을 읽어 하트비트 자리를 만드는 것은 당신 몫이다.
  - `update.error` ← UPDATE_ERROR_CODE
  - `messages.mailError` ← MAIL_ERROR_CODES
  - `recordTime.fileVsRecordMin` ← RECORD_TIME
  - `callCard` 새 키(4.1-5)
- 숫자와 코드만 올린다(counts 필터).
- 새 키가 더 필요하면 `CallPorts.kt`의 v3.4 묶음 끝에 더하고 보고서에 적는다.

## 이번 밤의 순서 (설계와 다름, 오케스트레이터 결정)
- 설계는 "r14-1 배포 → 48시간 실측 → r14-2"였다. 사용자가 "v3.4까지 배포"를 정해서 r14-1부터 r14-4까지 한 번에 배포한다.
- 48시간 실측은 배포 뒤 다듬기(v3.4.x)의 근거로 쓴다.
- 그래서 4.1의 판정과 통계는 실측 없이도 안전한 기본값으로 둔다.

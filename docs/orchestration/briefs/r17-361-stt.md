# 묶음 r17-361-stt: 밤을 다 쓴다 + DB 응급 처치 (v3.6.1, DESIGN_V7 2절 T1·T3a·D1)

공통 지침은 `docs/orchestration/worker-brief.md`. 기준 브랜치 `feature/r17-v361`, 자기 브랜치 `feature/r17-v361-stt`.

## 배경(실측)
밤 충전 6.6시간 중 자막 작업이 43%만 돈다. 11/10 01~04시는 시간당 약 45분 돌았는데 04~07시는 3시간에 39분, 그 사이 `hotSkips` 6→16, 온도 27~32℃, headroom 0.5~0.6. 원인(감사): `PowerPolicy`의 hot 판정 세 조건(headroom ≥ 0.85, 온도 ≥ 40℃, `slow`) 중 정상 온도에서 참이 되는 것은 `slow`뿐인데, rate = 작업 ms ÷ 오디오 ms라 짧은 꼬리 조각(Whisper는 30초 창 하나를 통째로 인코딩)의 rate가 크게 나와 `lastRate ≥ coldRates 중앙값 × 1.5`에 걸린다. 걸리면 YIELD → 즉시 재실행 → hot → 10분 미룸이 두 번 반복된다(`HOT_DELAY` 10분 < `COLD_AFTER` 20분). 같은 부풀린 rate 때문에 W2 `splitAhead`가 멀쩡한 2분 조각을 미리 반으로 쪼갠다.
또 배터리 실행은 `PowerStats.budget`의 `last=now` 자기 표시(P:333 근처)가 실행 중 `keepGoing`→`decide`에서 `Wait("gap")`에 걸려 조각 1개로 끝난다(11/9 배터리 17분에 녹음 0분). 상세는 `docs/reviews/v36_impl_review_20261107.md`의 "높음".
봉인 DB는 `dbPercent` 46·하루 +3.7%p. `trim()`이 `insert()`와 같은 트랜잭션에서만 불려, 100%가 되면 같이 실패한다.

## 할 일
- **T1 속도를 인코더 창 수로 정규화:** rate = 작업 ms ÷ (ceil(오디오 ms ÷ 30,000) × 30,000). 이 기준을 `rates`·`coldRates`·`lastRate`와 W1(9분 안에 들어갈지)·W2(`splitAhead`) 예상에 똑같이 쓴다(예상 시간 = 정규화 rate × 창 수 × 30초). 모든 조각을 표본으로 쓴다. **hot 대기 뒤 첫 조각은 식은 조각으로 본다**(한 번 걸려도 한 번만 쉬게 — `HOT_DELAY`와 `COLD_AFTER`의 관계 정리). 하트비트용으로 hot 사유를 나눠 센다: `hot{headroom, temp, slow}`(키는 `PowerStats`에 두고, `PhoneStatus`는 다른 묶음 담당이라 **`PowerText`/기존 power JSON 생성부에서 내보내는 범위까지만** — `PhoneStatus.kt`를 고쳐야 하면 보고서에 "오케스트레이터가 연결할 한 줄"로 적는다).
- **T3a 배터리 실행 회귀:** 실행 중 재판정이 자기 표시 때문에 `gap`에 걸리지 않게(시작 때의 budget을 쓰거나 실행 중에는 gap 조건을 건너뜀). 작업 연결 시험: 배터리 실행 한 번이 예산 안에서 조각을 2개 이상 이어 하는지.
- **D1 DB 응급 처치:** `CallRecordStore.trim()`을 `VaultPruneWork`(매일)에서 **별도 트랜잭션으로** 부른다. 자막 보존 `TRANSCRIPT_KEEP_DAYS` 14 → 7일, `dbPercent` ≥ 60이면 3일. 체크할 일의 인용문(`analysis_json`)은 그대로다. 통화 상세 화면이 자막 전문이 비었을 때 깨지지 않는지 확인("자막은 정리 7일 뒤 비워요" 같은 기존 문구가 14일이라고 말하면 고친다 — 화면 글 규칙 준수).

## 시험
순수 함수 시험으로: 7초 꼬리 조각(작업 50초)이 들어와도 `slow`가 참이 되지 않음, 2분 조각이 실제로 1.5배 느려지면 참, hot 대기 뒤 첫 조각이 식은 표본으로 들어가 두 번 연속 건너뛰지 않음, `splitAhead`가 꼬리 조각 뒤의 2분 조각을 쪼개지 않음, 배터리 실행이 예산 안에서 이어 감, `trim`이 `insert` 없이도 돌고 7일·3일 규칙을 지킴. 기존 `R16OneTest`·`R16TwoTest`·`R12EightTest`가 옛 rate 정의를 검사하면 설계대로 고친다.

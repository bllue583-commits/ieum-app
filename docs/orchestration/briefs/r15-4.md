# r15-4 지시문: 검토 반영 (v3.5, 기준 `feature/r15-v35` cb8b5ae)

공통 지침 `docs/orchestration/worker-brief.md`를 지킨다. 브랜치 `feature/r15-4-review`. 독립 검토(11/6 14시) 지적 중 아래만 고친다. 각각 시험 1개 이상.

1. **H1 메인 스레드 저장소 열기:** `StatusLights.withPhone`(약 222줄)의 `CallTranscriptionStore(app).use { it.failedCount() }`를 없애고, 실패 수는 IO에서 미리 읽어 넘긴다(`StatusLights.read` 또는 `SettingsScreen.refresh`의 IO 블록에서 읽어 입력 필드로). `withPhone`/`render` 경로에서 저장소·DB를 여는 곳이 없게.
2. **H2 카톡 성공한 날 알림:** "나와의 채팅"은 카카오톡이 푸시 알림을 띄우지 않을 수 있다. 카톡 성공이어도 06시 앱 알림을 **조용히(소리·진동 없이, 기존 채널 중 조용한 것 또는 setSilent)** 띄우되 첫 줄은 "카카오톡 나와의 채팅에 아침 보고를 보냈어요"로. 업데이트 대기 줄(`withUpdate`)이나 늦게 정리된 통화 줄(`withLate`)이 있는 날은 평소처럼 소리 있는 알림. 실패·미연결이면 지금처럼. 설정 문구도 "앱 알림은 조용히 와요"에 맞게.
3. **M1 [지금 보내 보기]:** 시험 전송은 `REPORT_DAY`·`KAKAO_LAST_SENT_MS`·카운터를 쓰지 않는다(따로 `kakaoTestSentDay` 같은 내부 키로 하루 1회만 제한, `ReportFetch.REPORT_BODY`처럼 r15-1 파일 안 상수). 그래야 새벽에 눌러도 05:30 정식 보고와 앱 알림이 막히지 않는다.
4. **M2 워치독·하트비트:** 하트비트 `kakao`에 `on`(MORNING_KAKAO, 없으면 true) 추가(`PhoneStatus.V35`·`putV35`·`v35`). `tools/inbox/watchdog.py`의 "카카오톡 보고가 안 갔어요"는 `on`이 참일 때만(키가 없는 옛 하트비트는 참으로 봄). 새 규칙 "카카오톡 연결이 풀렸어요": `linked=false`이고 `error`가 `TOKEN_`으로 시작하면 이슈. `test_watchdog.py`에 시험.
5. **M4 재큐 상한:** FAILED 되살림을 줄마다 총 2회까지(새 열 `requeue_count`, NULL=0, 기존 마이그레이션 방식), 사유가 `INTERRUPTED`인 줄은 1회까지.
6. **L5:** `ReportFetch`(약 107줄)의 `catch(e:Exception)`에서 `CancellationException`은 다시 던진다. 같은 패턴이 `pipeline/report/*`에 더 있으면 같이.
7. **L7:** `KakaoReport.link` 성공 뒤 설정 저장을 `withContext(Dispatchers.IO)`로.
8. **L1:** 키가 없는 빌드에서는 `AuthCodeHandlerActivity`를 끈다(`android:enabled="${kakaoEnabled}"`, build.gradle에서 키 유무로 "true"/"false").
9. **L10:** `tools/report_check.py`의 구분자 `[-.\s)]{0,3}`로 넓히고 메일 주소 검사 추가, 시험.
10. **L2:** `MainActivity.kakaoTarget`의 `dayMs`를 최근 5년~내일 범위로 제한(벗어나면 오늘).

# r10-1 전화 상태 감지 (v2.9)

공통 지침 `docs/orchestration/worker-brief.md`를 먼저 읽고 따르세요. 브랜치 이름: `feature/r10-v29-r1`. 기준은 `feature/r10-v29`(v2.8 완성본).

설계: `docs/DESIGN_V3.md` 6.1절 **r10-1** 전부. 목적: 통화가 끝나면 앱이 바로 알아차려 발견 → 자막 → 업로드를 즉시 돌린다. v3.0 통화 카드도 이 감지를 쓴다.

## 담당 파일
- `pipeline/call/CallStateReceiver.kt`(신설, 매니페스트 `android.intent.action.PHONE_STATE` 수신기, exported 필요 — 시스템 브로드캐스트), `pipeline/call/CallSession.kt`(신설, 프로세스 싱글턴 + `SecureSettings`에 마지막 상태 저장)
- `AndroidManifest.xml`(권한 `READ_PHONE_STATE`, 수신기)
- 처음 설정 카드(`screens/HomeScreen.kt`의 setup 단계)와 설정 "연결" 묶음(`screens/SettingsScreen.kt`)에 단계 "통화가 끝난 걸 바로 알아차리기"(이유 문장 먼저, 그다음 권한 요청) — **이 두 파일은 단계 하나 더하는 최소 수정만**(r10-2가 설정 "정리" 묶음에 스위치를 더합니다).
- `AutomaticRecordingDiscovery.kt`에 일회성 작업 `ieum.discovery.aftercall`(`setExpedited`, 15초 뒤) 추가 → 발견 사이클 → 새 파일이 있으면 자막 작업 즉시 → 자막 끝나면 즉시 업로드(`CallTranscriptionWork`/`CallRecordWork` 체인에 필요한 최소 수정). 통화기록 트리거(45초)와 15분 주기는 안전망으로 유지.

## 상태 기계
`IDLE → RINGING(number) → OFFHOOK → IDLE`, `IDLE → OFFHOOK(outgoing) → IDLE`. 같은 상태의 중복 브로드캐스트는 무시하되 번호가 비어 있다가 채워지면 번호만 갱신. 번호는 `EXTRA_INCOMING_NUMBER`(READ_CALL_LOG가 있어 받을 수 있음)를 `kr.callbrief.core.PhoneKey.of`로. `IDLE`로 돌아오면(직전이 OFFHOOK) `CallSession.ended`를 확정하고 `aftercall` 작업을 건다. 개인 번호(`personal_numbers`)·제외 번호 통화는 아무 일도 하지 않는다.

## 다른 묶음과의 약속(그대로 지켜 주세요)
- `CallSession.State { IDLE, RINGING, OFFHOOK }`, `CallSession.current(): Snapshot(state, phoneKey:String?, direction: IN|OUT|null, sinceMs)`.
- 통화가 끝나면 `CallSession.listeners`(`CopyOnWriteArrayList<(CallEnd)->Unit>`)에 `CallEnd(phoneKey:String?, direction, startedMs, endedMs, answered:Boolean)`를 알립니다. r10-2(통화별 알림)가 여기에 붙고, v3.0 통화 카드도 씁니다. **IDLE 처리 끝에 `CallFollowupNotice.onCallEnded(context, end)` 한 줄을 호출하되, 그 객체가 아직 없으면(r10-2가 만드는 중) 호출을 주석으로 남기고 보고서에 적으세요.**
- v3.0을 위해 `CallSession.pendingOutgoing(number, atMs)` 자리를 비워 두지 말고, `OFFHOOK`이 RINGING 없이 오면 `direction=OUT`으로 적습니다(번호는 모를 수 있음 → null).

## 시험
- Robolectric: PHONE_STATE 브로드캐스트 순서(RINGING→OFFHOOK→IDLE, 중복, 번호 지연, 바로 OFFHOOK)에서 `CallSession` 상태와 `aftercall` 작업 등록(WorkManager 테스트 초기화)이 맞음. 개인 번호면 아무 일도 없음. 프로세스가 죽었다 살아나도 SecureSettings에서 상태 복원.

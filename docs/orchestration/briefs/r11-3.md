# r11-3 시험과 안전장치 (v3.0)

공통 지침 `docs/orchestration/worker-brief.md`를 먼저 읽고 따르세요. 브랜치 이름: `feature/r11-v30-r3`. 기준은 `feature/r11-v30`(v2.9 완성본 + r11-1·r11-2가 합쳐진 뒤 — 오케스트레이터가 알려 준 커밋).

설계: `docs/DESIGN_V3.md` 7.3 **r11-3**, 7.4 확인 기준.

## 담당
- 설정 신호등에 "통화 카드" 줄(`StatusLights`: 오버레이 권한·READ_PHONE_STATE·역할 여부, target=통화 카드 묶음).
- 권한이 사라지면 처음 설정 카드에 다시 나타남(r11-1이 했으면 시험만).
- `CallCardService`가 10분 넘게 살아 있으면 스스로 종료(r11-1이 했으면 시험만).
- 카드가 뜬 횟수·실패 사유(권한 없음, 번호 없음, 카드 없음)를 설정 `CARD_STATS`(JSON)에 세고 하트비트 `callCard:{shown,noPermission,noNumber,noCard}`(`PhoneStatus.Watch` 필드, `PhoneStatusTest` 키 목록). `tools/inbox/watchdog.py`에 "카드 실패가 많으면" 규칙 한 줄.
- 에뮬레이터 시험 스크립트 `tools/device/call_card_test.sh`(7.4 시나리오: appops SYSTEM_ALERT_WINDOW allow, `cmd role add-role-holder`, PreviewSeed로 01011112222 카드, `adb emu gsm call/accept/cancel`, `dumpsys window windows`에서 오버레이 창, 스크린샷 `evidence/shots/card_*.png`, `dumpsys activity services`에 서비스 없음, 모르는 번호·개인 번호 시나리오). **워크플로 파일(`.github/workflows/device-test.yml`)은 고치지 말고**, 스크립트를 어느 단계 뒤에 어떤 명령으로 부르면 되는지 보고서에 적으세요(오케스트레이터가 넣습니다).
- Robolectric: 서비스 수명, 역할 없을 때 발신 카드 없음, 권한 없을 때 알림 폴백, 카드 2단계 그리기 — r11-1·r11-2가 만든 시험에 빠진 것만 보강.

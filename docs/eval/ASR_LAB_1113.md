# 자막 실험실 11/13 (r19-lab) — 정답이 있는 공개 음성으로 엔진 (가)·(나)·(다)와 기준 자막 방법을 잰다

> 11/13 실행 결과. 표는 `tools/eval/asrlab/summarize.py`가 `scores/*.json`에서 채운다 — 손으로 옮긴 숫자는 없다.

## 0. 결론

- **5.2 규칙 2의 정확도 조건(이 음성 기준)**: (다) SenseVoice의 "(가) 대비" 오류율은 4.5~9.2%로 15% 아래, 묵음 환각은 통화당 0개 — **잡음이 큰 조건(잡담 SNR 10 dB, 19.7%)만 넘지 못한다**. 정답 대비로는 (다)가 모든 묶음에서 (가)보다 1.3~4.4배 틀린다(초벌용, 확정 불가).
- **초벌·확정 숫자 불일치**: 확정 (가)의 숫자 중 초벌 (다)에 없는 것이 D 11%, E 21%, A 24%, B 32~33%, 이름은 D 46% — 녹음 23개 중 20개에 불일치가 1개 이상 → 5.3의 수정 경로는 예외가 아니라 거의 매 통화의 일이다.
- **q5_0 = q8_0**(구간 안, 숫자도 거의 같음) → (나)의 값은 속도뿐.
- **기준 자막**: large-v3 하나는 turbo보다 낫지 않고(A 4.7% 대 2.6%), 같은 계열 합의는 오류의 14~21%만 드러낸다. **large-v3 + (가) + (다) 3자 대조로 다른 곳만 사람이 보면** 오류 글자의 73~97%가 드러나고(낭독·TTS) 남는 오류 0.1~0.3%, 볼 양은 분당 약 7~10곳(숫자 구간 0.5~4.4곳). 실제 표본에는 이 방법을 권한다(`reference.py`). 숫자는 불일치가 없어도 한 번 듣는다.
- **새로 안 것**: 앱의 묵음 지우기 하한 0.006이 조용한 녹음(FLEURS의 51%)의 말소리 절반 이상을 지워 (다)의 오류율을 4.7% → 22.1%로 만든다. 실제 통화 녹음의 음량을 먼저 확인해야 한다(6절 1).
- 한계: 실제 통화가 아니다(낭독·TTS·흉내 낸 전화 음질), 표본이 작다((가)는 묶음당 4~25분, 문장 30~115개). 5절.

## 1. 방법

- **앱과 같은 조각**: 녹음 → 16 kHz 모노 → 2분 원조각(경계 ±2초 최저 에너지) → 묵음 지우기(30 ms 창, 하한 0.006, 1.5초 미만 틈 유지, 앞뒤 0.3초) → 2분 이하 조각(`apppipe.py`, 앱 `PipelineAudioMath.kt` 옮김, 상수는 시험으로 고정). 세 엔진이 같은 조각을 받는다(앱 측정대 `BenchEngines.kt`와 같음).
- **(가)/(나)**: whisper.cpp **1.7.6**(앱 판)에 링크한 `whisper_app_run.cpp` — 앱 JNI `transcribeChunk`의 기본값 그대로(그리디, temperature_inc·best_of 라이브러리 기본, suppress_nst 끔, token_timestamps, no_context, language ko, 초기 프롬프트 없음 — 앱 `PROMPT_ENABLED=false`, flash_attn 끔). 저장 직전 정리(`TranscriptClean`: 알려진 환각 문구, 3번 이상 반복)도 같게. 스레드는 1(폰은 4~6) — 그리디라 결과 차이는 부동소수 순서 정도.
- **(다)**: SenseVoice-Small int8 2024-07-17, sherpa-onnx **2.0.1**(pip, 앱과 같은 판), language ko, ITN 켬, Silero VAD(threshold 0.5, 최소 묵음 0.5초, 최소 말 0.25초, 창 512, 최대 20초) — `BenchEngines.kt`와 같음.
- **기준 자막 후보**: Whisper **large-v3**(turbo 아님) ggml q5_0을 whisper.cpp 1.9.5로, 앱과 같은 `whisper_full` 설정(그리디, 문맥 끔) — 이하 `lv3`. 계열이 다른 대조 모델로 SenseVoice(다)와 zipformer-korean. 처음 계획한 faster-whisper large-v3(f16 3 GB → int8)는 이 작업 환경의 메모리 한도(6.26 GB, 다른 작업자의 gradle 약 3.2 GB와 공유)에서 두 번 메모리 부족으로 죽어 바꿨다(`run_engines.py --engine lv3fw`로 남김). 그래서 이 문서의 '큰 모델'은 f16·빔 탐색이 아니라 **양자화·그리디** large-v3다.
- **채점**: `tools/eval/ko_cer.py`의 정규화(숫자 → 정수, 문장부호·띄어쓰기 무시). 녹음 전체 자막을 정규화해 글자 정렬로 정답 문장별로 나누고, 문장별 편집 수의 합/정답 글자 수의 합. 95% 구간은 문장 부트스트랩 2,000번, 엔진 간은 같은 문장의 짝 부트스트랩. 숫자·이름은 통화(녹음) 단위로 앱 `KoCer.numberHits/nameHits`와 같은 규칙(정규화한 숫자 연속의 중복 집합, 이름 포함 여부). 묵음 환각 = 원래 시각으로 되돌린 자막 조각의 80% 이상이 정답 말소리 밖. 반복 고리 = 정규화 글자열에서 2~20자 단위가 4번 이상 연속.
- **수준 맞추기**: 원본 음량이 -54~-10 dBFS로 제각각이라(FLEURS) 문장마다 말소리 수준을 -26 dBFS로 맞췄다(1차 실행에서 앱의 하한 0.006이 조용한 FLEURS 문장을 통째로 지웠다 — 6절 발견 1).

## 5. 한계 — 실제 표본으로만 확인되는 것

- **음성이 실제 통화가 아니다.** 낭독(A·B·E), 혼자 하는 말(C), TTS(D)다. 실제 통화의 겹쳐 말하기, 상대 쪽만 좁은 대역인 녹음, 삼성 통화 녹음의 실제 코덱·음량, 업무 말투·사투리·말 더듬은 없다. 전화 음질은 μ-law/Opus로 흉내 냈고 AMR은 쓰지 못했다.

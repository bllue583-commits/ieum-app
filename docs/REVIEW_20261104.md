## 1. 버그 (심각도 순)

1. ✔ **"통화 시각 미상"이 자동 발견 경로에서는 아직 안 고쳐짐.** 11/4 수정(2bcc9d5)은 `local_files.filename_time_candidate_ms`를 *읽는* 쪽만 바꿈. 자동 발견 경로 `GeneralLocalStore.finalizeDiscoveryAlias`(:240)는 이 열에 **NULL을 INSERT**하고 UPDATE에서도 채우지 않음. 파일명 시각을 쓰는 함수는 `importSelected`(:148-152)뿐이며 main 호출 없음(테스트만).
   - 연쇄: `call_records.started_ms` NULL → 통화기록 대조 제외(CallRecordStore.kt:516), 지난 녹음이 `isOld` 판정을 못 받아 `b-` 묶음 대신 하나씩 live 업로드, 오늘 통화·저녁 보고 날짜 틀어짐.
   - 수정: `finalizeDiscoveryAlias`에서 `RecordingNames.startedAt(d.name)?.toEpochMilli()`를 INSERT/UPDATE 모두에 저장. 파일명에 시각이 없으면 `modified - duration` 대체.
   - 확인: 실기기 요청 파일의 `통화 시각:` 줄 또는 `local_files` 열 값.
2. ✔ **7분 넘는 통화는 자막이 끝나지 않을 수 있음.** Whisper가 일반 WorkManager 작업이고 `setForeground`/`setExpedited`/FOREGROUND_SERVICE 없음(grep 0건). 10분 제한에 걸리면 청크 중간 결과를 버리고 QUEUED로 되돌림(CallTranscriptionRunner.kt:75,86) → 매시간 10분씩 CPU만 쓰고 재시작. JNI `cancel` 미호출로 진행 중 청크는 끝까지 돎. `recoverRunning`(:59)이 RUNNING을 QUEUED로 되돌려 이중 실행 가능.
   - 수정: 청크 단위로 중간 결과 저장·이어 하기 + foreground 서비스(`dataSync`) 또는 실행당 예산 후 재큐잉.
3. ✔ **전화번호가 inbox 요청 본문에 샘.** SMS 기록 id가 `sms:<번호>:<id>`(MessageWork.kt:93)이고 `CallInbox.job`(:93)이 이 id를 `"id"` 필드에 그대로 씀. 파일명만 해시. → `recordKey` 해시를 쓰고 결과 매핑도 그 키로.
4. **결과 적용 중복 가능.** 시간당 `ieum.calls.inbox`와 즉시 `ieum.calls.analysis`가 고유 이름이 달라 동시 실행 가능(CallSinkImpl.kt:30-56). `applyAnalysis`(CallRecordStore.kt:297)에 `state!=ANALYZED` 재확인 없음 → 체크할 일 중복 생성. → 트랜잭션 안 재확인 또는 `runInbox` 프로세스 락.
5. **결과 파일 실패가 묻힘.** 파싱 실패 → `getOrDefault(emptyList())` → **파일 삭제**(CallRecordWork.kt:44,53). `applyAnalysis` 예외는 IOException만 잡아(:87) 독이 든 파일 하나가 매시간 작업 전체를 실패시킴. GitHub 409(동시 커밋)·401이 `ClaudeCallException`으로 재시도 없이 실패(CallInbox.kt:35). → 파싱 실패 파일은 `bad/`로, 기록별 try/catch, 409는 재시도.
6. **서명 키가 `IEUM_INBOX_TOKEN`에서 유도됨**(release-apk.yml:45-47, tools/derive_signing_key.py). 이 토큰은 APK 안 평문 `BuildConfig`(app/build.gradle.kts:20-22). APK만 있으면 토큰 → 서명 키 재생성 → 위조 업데이트 서명 가능. 토큰이 바뀌면 서명이 달라져 폰 재설치 필요. → 별도 고정 비밀 `IEUM_SIGNING_SEED`로 분리. 기존 설치본과 같은 인증서를 유지하려면 현재 키로 한 번 이어 가는 전환 절차 필요. 토큰은 최소 권한으로.
7. **처음 정리 완료가 너무 일찍 켜질 수 있음.** `FIRST_PASS_DONE` 조건이 `old.isEmpty() && bound==null`(CallRecordWork.kt:83)인데 발견은 주기당 4건(NativeDiscoverySession.kt:87) → 큐가 잠깐 비면 10월 녹음이 남아도 완료. → "발견 완료 + 대기 문서 0"을 조건에 추가.
8. **아침 정리 `due` 누락 시 기한 삭제.** `rewrite`의 `t.optString("due")`(CallRecordStore.kt:497)가 키 없으면 "" → `dueItems`(:367)에서 사라짐. → 키 없으면 건너뛰기.
9. **인용 불일치·날짜 형식이 조용히 버려짐.** 자막은 세그먼트를 `""`로 붙여(CallTranscriptionRunner.kt:78) 공백이 불규칙 → 모델이 정리해 복사하면 `filter`(:240)에서 정상 항목도 버려지고 건수 기록 없음. `due`는 ISO 검증 없음 → "2026-11-5"는 저장되고 보고(:368 정규식)에서 영영 빠짐. → 공백·문장부호 정규화 비교, 버림 카운터, `due` 정규화. 예약 작업 지시문에도 "쓰기 전에 quote 부분 문자열·due 형식 자체 검증" 한 줄 추가 권장.
10. **알림 Doze 취약.** OneTimeWork(CallDigestWork.kt:61-80)라 정시 보장 없음. 늦게 실행되면 저녁 알림이 다음날 "오늘 통화 0건". 부팅 수신기 없음(`ensure`는 설정/시작 때만). 알림 권한 2회 거절 후 대체 동작 없음. → `setExactAndAllowWhileIdle`(개인 설치 앱이라 `USE_EXACT_ALARM` 가능) + 예약 시각 대비 N시간 지연 시 건너뛰기 + BOOT_COMPLETED.
11. **원본 녹음이 암호화 금고에 영구 보관**(GeneralLocalStore.kt:244-256), 삭제 경로 없음 → 달 단위 수 GB. → 자막 완료 후 보존 기간 지나면 blob 삭제.
12. **메모리.** 파일 전체 `ByteArray` + 전체 PCM + `speechOnly` 복사본(CallTranscriptionRunner.kt:142-146). 30분 넘는 통화는 OOM 위험(Error라 `catch Exception`에 안 잡힘).

## 2. 알고리즘·설계 개선

- **통화 종료 즉시 감지**: 15분 폴링 + 2회 안정 관찰로 15~30분 지연. `Constraints.addContentUriTrigger(CallLog.Calls.CONTENT_URI)`로 통화기록이 쌓이면 발견·자막을 즉시 깨우기(READ_CALL_LOG 이미 있음). 안정화 대기는 유지.
- **STT 속도**: `GGML_CPU_ARM_ARCH "armv8-a"` 고정(CMakeLists.txt:15) → S25 전용이면 dotprod/i8mm/fp16으로 올려 벤치마크. 5분 청크마다 **모델 재로드**(CallTranscriptionRunner.kt:120) 제거. `initial_prompt`에 장부의 사람·업체명·공종 용어(ieum_whisper.cpp:125-128). 발열 기준 SEVERE → MODERATE, 통화 중(전화 상태) 일시정지.
- **사람 식별**: `+82` 정규화가 통화(`counterpartKey`, 숫자만)와 SMS(`phoneKey`, 82→0)에서 달라 id가 어긋남 → 공통 함수. `call_links`가 분석 후에야 생겨(CallRecordStore.kt:320) 분석 전 중복 사람 발생 가능. 이름 매칭이 공백 제거 문자열이라 "김민수 과장"≠"김민수". 통화기록 매칭 창(−60~+120초, FirstPass.kt:56-71)이 벨 긴 수신 통화를 놓칠 수 있고 후보 둘이면 포기.
- **DB 16MB 상한**(ProtectedDatabase.java:34): 평상시 3~5MB 추정으로 여유 있으나 한도 도달 시 저장소 전체가 `REVIEW_REQUIRED`로 멈춤. 크기 감시·경고 없음 → 설정 "지금 상태"에 내부 표시 + 80% 경고. FAILED/WAITING/미분석 자막은 14일 삭제 대상이 아니라 영구 보존.
